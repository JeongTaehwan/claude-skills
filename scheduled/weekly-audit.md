# 주간 점검 지시서

`~/.claude/scheduled-tasks/weekly-skill-audit` 가 매주 이 파일을 읽어 실행한다.
**등록된 프롬프트는 "이 파일을 읽고 따르라"뿐이므로, 동작을 바꾸려면 재등록하지 말고 이 파일을 고치면 된다.**

저장소: `/Users/jeongtaehwan/Documents/workspace/skills`

---

## 왜 이 구조인가

스케줄 실행은 매번 문맥이 새로 시작한다. 지난주에 무엇을 봤고 무엇을 넘어가기로 했는지
기억할 방법이 없으면, 같은 알림을 매주 반복하다가 결국 아무도 안 읽게 된다.

그래서 기억을 두 군데 파일로 둔다.

- `reports/state.json` — 항목별 최초 발견일·연속 횟수·처리 상태(open/acknowledged/wontfix/resolved)
- `reports/YYYY-MM-DD.md` — 매 실행의 리포트

`audit.py` 가 state.json 을 읽고 쓰므로, 리포트는 전체 덤프가 아니라 **달라진 것**만 담는다.

---

## 실행 절차

### 1. 기계 점검

```bash
cd /Users/jeongtaehwan/Documents/workspace/skills
python3 scripts/audit.py --out reports
```

링크 380여 개와 GitHub 저장소 70여 개를 확인하므로 몇 분 걸린다. 끝나면
`reports/<오늘>.md` 가 생기고 `reports/state.json` 이 갱신된다.

### 2. 리포트를 읽는다

조치 대상은 두 절뿐이다.

- **새로 생긴 것** — 이번 주에 처음 나타난 문제
- **N회 이상 방치된 것** — 계속 나오는데 아무 결정도 안 한 항목

"이번 주 변화 없음" 이면 3단계를 가볍게만 하고 끝낸다. 없는 일을 만들지 마라.

### 3. 외부 변화 확인 (스크립트가 못 하는 것)

**먼저 `reports/` 에서 최근 리포트 2개를 읽어라.** 거기 이미 적힌 내용은 다시 적지 않는다.
이 단계의 목적은 매주 같은 뉴스를 반복하는 게 아니라 **지난번 이후 달라진 것**을 잡는 것이다.

웹 검색으로 확인한다.

- 새 Claude 모델이 나왔는가 — 나왔다면 모델 ID, 그리고 스킬 문서에 적힌 모델 정보가 낡았는지
- Claude Code 의 스킬·플러그인·메모리 구조에 변경이 있었는가 — 있다면 이 저장소의 배치가 여전히 맞는지
- 라이브러리가 인용하는 도구 중 메이저 버전이 바뀌어 문서 URL 이 옮겨간 것이 있는가

확인한 결과를 오늘 리포트 파일 끝에 이어 붙인다.

```markdown
## 이번 주 확인한 외부 변화

- (없으면) 확인했으나 지난 리포트 이후 달라진 것 없음.
- (있으면) 무엇이 바뀌었고, 이 저장소의 어느 파일 어느 부분이 낡았는지 지목
```

낡은 곳을 찾았으면 **파일 경로와 해당 줄까지** 적어라. "문서를 갱신해야 함" 같은 말은 다음 주에 아무 도움이 안 된다.

### 4. 하지 않는 것

- **스킬을 삭제하지 않는다.** 발동 0회는 "안 쓰였다"와 "안 떴다" 두 가지 뜻이고, 이 둘은 그 기간에 무슨 작업을 했는지 알아야 구분된다. 스크립트도 스케줄 실행도 그걸 모른다.
- **레퍼런스 항목을 삭제하지 않는다.** archived 저장소나 2년 정체가 곧 무효는 아니다. 고전 논문과 완결된 튜토리얼은 갱신될 이유가 없다. 도구·프레임워크일 때만 대체재를 제안한다.
- **main 에 커밋하거나 푸시하지 않는다.**
- **스킬 파일을 고치지 않는다.** 제안만 하고 결정은 사람이 한다.

리포트 파일을 쓰는 것과 state.json 을 갱신하는 것만 허용된 쓰기다.

### 5. 요약

마지막에 한 문단으로 정리한다. 이 문단만 읽어도 열어볼지 말지 판단이 서야 한다.

- 새로 생긴 문제 몇 건, 그중 지금 봐야 할 것은 무엇인지
- 방치된 항목이 있으면 그게 무엇이고 결정을 어떻게 내리는지 (`--wontfix` / `--ack` 명령 포함)
- 외부 변화가 있었으면 한 줄

변화가 없으면 "변화 없음"이라고만 하고 끝낸다. 분량을 채우지 마라.

## 사람이 결정을 기록하는 법

리포트에 나온 키를 그대로 쓴다.

```bash
# 안 고치기로 결정 — 다음부터 조용해진다
python3 scripts/audit.py --wontfix repo:google/eng-practices:archived --note "가이드 내용은 유효, 저장소만 동결"

# 처리 중 — 계속 추적하되 방치로 올라오지 않는다
python3 scripts/audit.py --ack link:https://example.com/foo --note "대체 자료 찾는 중"

# 다시 열기
python3 scripts/audit.py --reopen skill:slow-network-ux:unused

# 현재 열린 항목 전부
python3 scripts/audit.py --list
```
