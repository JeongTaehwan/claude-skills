# 끼니(Kkini) 리서치 — 식재료 가격 데이터 & 배달 매장 필터

조사일: 2026-09-12. WebSearch는 정상 동작. WebFetch는 `kamis.or.kr`, `data.go.kr`, `price.go.kr`, `velog.io`가 이번 조사에서도 프록시에 차단됨(`market.md` 머리말과 동일 현상, 새로 확인). 해당 항목은 검색 스니펫·2차 자료로 대체했고 각주에 표기. 본 문서는 `market.md` 4절(API 한도)·5절(개인정보)을 전제로 하며, 거기서 다룬 내용은 요약 인용만 하고 반복 조사하지 않았다.

**결론(발견만)**
1. 1인 개발로 "레시피 1인분 재료비"를 계산하려면 현실적 선택지는 **KAMIS(직접) 또는 공공데이터포털 경유 aT/축평원 API**뿐이다 — 둘 다 농·축·수산물 원물 가격은 있으나, 정확한 무료 호출 한도를 1차 문서로 확인하지 못했다(KAMIS는 숫자 자체가 안 보이고, 공공데이터포털은 표준 정책인 일 1,000/10만 건이 적용될 것으로 보임).
2. KAMIS는 가공식품 카테고리(간장·된장·고추장·김치 등)를 별도로 제공하지만, 일반 슈퍼마켓 브랜드별 양념(특정 제조사 참기름, 다진마늘 등)이나 공산품(식용유, 소금 브랜드별)까지는 커버 범위가 확인되지 않는다 — 이런 품목은 가격 데이터가 없거나 고정 [추정]값으로 처리해야 할 가능성이 높다.
3. 한국소비자원 참가격(price.go.kr)은 대형마트·편의점 간 가격 비교가 강점이라 매력적이나, 실제 Open API 가동 여부가 상충되게 확인되어 그대로 의존하기엔 불확실성이 크다.

## 3. 배달 가능 매장 필터의 가능성

|---|---|---|
| 배달앱(배민·요기요·쿠팡이츠) 공식 오픈 API | **없음** — market.md 4절에서 이미 확인(okky.kr 커뮤니티 다수 질문)[14]. 이번 조사에서 새로 확인된 사실: 각 앱의 **웹사이트**(baemin.com, yogiyo.co.kr/mobile)는 브라우저에서 주소를 입력해 배달 가능 매장 목록을 사람이 직접 볼 수 있는 UI를 제공함 — 다만 이는 공식 API가 아니라 일반 웹페이지이므로 자동 수집 시 스크래핑과 동일한 ToS 리스크를 진다[15][추정: 페이지 구조·파라미터는 미확인] |
| 카카오 로컬 API 카테고리검색(FD6, 음식점) | **배달 가능 여부 필드 없음.** 응답 필드는 `id, place_name, category_name, category_group_code, phone, address_name, road_address_name, x, y, place_url, distance` 등으로 확인되며[16], "배달"을 나타내는 필드는 이 목록에 없다 | 반경 검색으로 음식점 목록·주소·전화번호까지는 얻을 수 있으나 배달 가능 여부는 별도 수단이 필요 |

**결론(발견만)**
1. 집주소로 "배달 가능한 매장"을 필터링하려면 배달앱의 실시간 배달권 데이터가 필요한데, 이는 공식으로 공개되어 있지 않다 — 카카오/네이버 지역검색 API는 "그 주소 근처에 어떤 음식점이 있는지"까지만 알려주고 "그 음식점이 이 주소로 배달되는지"는 알려주지 못한다.
2. 지금 코드로 안정적으로 만들 수 있는 최대치는 **"반경 내 음식점 목록 + 주소/전화번호/카카오맵 링크"**까지이며, 실제 배달 가능 여부·배달비·예상 도착시간은 사용자가 배달앱에서 직접 확인해야 하는 정보로 남는다.
3. 배달앱 앱으로 바로 연결하는 것은 공식 딥링크 문서가 없어 스킴 자체의 존재·안정성을 전제할 수 없고, 웹사이트 스크래핑도 market.md가 이미 지적한 ToS·안정성 리스크를 그대로 물려받는다.

## 4. 주소 저장의 법적 최소선

market.md 5절 인용: "위치를 서버로 전송·저장하면 방송통신위원회에 위치기반서비스사업 신고가 필요할 수 있다. 기기 내에서만 일시 처리하고 서버 전송·저장을 하지 않으면 신고 대상에서 빠질 가능성이 있으나, 서비스 구조에 따라 갈리므로 실제 저장 여부가 정해지면 재검토가 필요하다 [추정]." 이번 조사에서 이 지점을 별도로 더 파봤다: 법무법인 칼럼 등 2차 자료들은 "GPS 좌표·Wi-Fi AP·기지국 Cell 정보 등을 **수집**하면 신고 대상"이라는 기준을 제시하면서도, "저장하지 않고 단말기 내에서만 일시적으로 처리하거나 외부 전송이 없는 경우 신고대상에서 제외될 가능성이 있다"고 설명한다[19][20]. 즉 집주소를 기기(로컬 스토리지)에만 저장하고 서버로 전송하지 않는 구조라면 위치기반서비스사업 신고 의무에서 빠질 가능성이 있다는 것이 2차 자료들의 공통된 논조이나, 이는 "정확한 판단은 서비스의 구체적 기술 구조를 바탕으로 법률 전문가 검토가 필요하다"는 단서가 항상 붙는다 [추정, 1차 법령·유권해석 미확인]. 개인정보 처리방침 의무는 신고 여부와 별개다 — 집주소가 개인정보인 이상(정확한 주소는 개인 식별·결합 가능성이 높은 정보), 이를 기기에만 저장하더라도 "수집"에는 해당하므로 처리방침 게시 의무(개인정보보호법 제30조)는 그대로 적용된다고 보는 것이 안전하다 [추정].

## 확인 못한 것 / 후속 필요

- KAMIS Open API의 정확한 무료 호출 한도(숫자) — WebFetch 차단으로 1차 문서 확인 불가, 콘솔 가입 후 직접 확인 필요.
