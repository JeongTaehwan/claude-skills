# 끼니 — 화면 흐름 (docs/ux/flows.md)

> 상태: 초안. `docs/requirements.md`(미승인 초안) 기준. 요구사항이 바뀌면 이 문서도 다시 그린다.
> 표기: `[제안]` 화면 요소 중 요구사항에 문구·형태가 없어 이 문서가 채운 것 · `[미정 XX-OQ-NN]` 기존 미정 질문을 가리킴 · 본문 괄호 안 R-ID는 그 문장의 근거.

## 1. 전제 — 화면이 갈리는 미정 항목, PM 추천대로 그린다

| 항목 | 이 문서가 가정하는 답 | 다른 답이 나오면 무엇이 바뀌는가 |
|---|---|---|
| `[미정 KK-OQ-01]` | 앱이 갈래까지 정한다. 사용자는 먼저 묻지 않는다(MO는 DC 카드 안의 전환 요소) | "사용자가 먼저 고른다"가 되면 첫 화면이 갈래 3지선다가 되고 DC 카드는 그 다음에 온다 — MO가 DC의 하위 요소라는 구조 자체가 깨진다 |
| `[미정 DC-OQ-01]` | 1개 + 거절 버튼 1개. 2번째 후보 동시 노출 없음 | "3개 중 고르기"가 되면 DC는 목록/캐러셀 레이아웃이 되고 RE(거절)가 무의미해져 화면을 다시 설계해야 한다 |
| `[미정 DC-OQ-02]` | 콜드스타트도 바로 카드를 낸다(표본 부족 문구로) | "취향 입력을 먼저 받는다"가 되면 흐름(a) 전체가 바뀌어 DC 이전에 PR 온보딩 화면이 먼저 온다 |
| `[미정 DC-OQ-03]` | 같은 날 재방문 시 같은 결정 고정. 하루 거절 상한 5회 | "열 때마다 새로 뽑기"가 되면 하루 1건 가정이 깨져 HI 목록·북극성 분모가 흔들리고 흐름(c)가 사라진다 |
| `[미정 PR-OQ-02]` | 미입력은 "아직 모름"(3상태) | "미입력=제약 없음"이 되면 콜드스타트 첫 카드의 안전 안내 문구가 불필요해지지만 안전 리스크 자체는 남는다 |

이 다섯 개 외의 미정(HI-OQ-01/02, MO-OQ-01, PR-OQ-01, KK-OQ-02/05, DC-OQ-04/05)도 화면 문구에 등장하는 곳마다 해당 R-ID·OQ-ID를 각주처럼 표시한다.

## 2. 핵심 흐름

### (a) 첫 실행 — 콜드스타트 (프로필 0, 기록 0)
1. 앱 실행 → 입력 없이 바로 계산 시작 (DC-R04, DC-R10)
2. 로딩 "고르는 중" (DC-R05)
3. 카드 노출: 음식명·갈래·이유줄="아직 취향을 몰라서 오늘은 무작위로 골랐다" (DC-R08, DC-OQ-02 추천)
4. 카드 위/아래에 안내 한 줄 "못 먹는 음식이 있으면 먼저 알려주세요" → 누르면 PR로 이동, 건너뛰기 가능 (PR-OQ-02 추천, PR-R05)
5. 갈래는 기본값이 이미 선택돼 있고 바꿀 수 있음, 배달·포장은 "아직 없음"으로 보임 (MO-R01~04, KK-OQ-01)
6. 이후 사용자는 거절(b) 또는 확인(HI-R01)으로 진입

### (b) 평소 저녁 — 열기 → 카드 → 채택/거절 → 확정
1. 앱 열기, 오늘 아직 미확정이면 헤더 "오늘 저녁 추천" (DC-R09)
2. 로딩 "고르는 중", 직전 카드 안 남김 (DC-R05)
3. 카드 노출: 음식명·갈래·이유줄(DC-R02, DC-R03), 노출 시각 기록(DC-R11)
4. 분기
   - 채택: "이걸로 먹었다" 탭 → 헤더가 "오늘은 <음식>으로 정했다"로 전환 (HI-R01, DC-R09), HI 기록 생성(미확인 상태로 시작, HI-R02)
   - 거절: 거절 버튼 탭 → RE 사유 시트 노출(RE-R03) → 사유 선택 또는 건너뛰기 → 즉시 새 카드, 방금 거절한 음식은 그날 재노출 안 함(RE-R02), "안 좋아함"이면 이후 감점(RE-R04), 거절 횟수 기록(RE-R06)
5. 4의 거절이 반복되면 (d)로 이어짐

### (c) 같은 날 다시 열기
1. 미확정 상태로 재방문 → 새로 계산하지 않고 같은 카드를 그대로 고정 표시 (DC-OQ-03 추천) — 새 카드를 받는 유일한 방법은 (b)의 거절뿐, 별도의 "다시 정하기" 버튼은 없음(있으면 거절과 기능이 겹친다 → 6절 미정 제안)
2. 확정 상태로 재방문 → "오늘은 <음식>으로 정했다"만 표시, 거절·확인 버튼 모두 숨김(이미 끝난 결정이라 조작 대상이 없음, DC-R09)

### (d) 거절 상한 도달
1. 5번째 거절 후 새로 생성된 카드는 더 이상 거절할 수 없음 — 거절 버튼이 상한 문구로 바뀜(RE-R05, 문구는 `[제안]`, 6절 참조)
2. "이걸로 먹었다"만 남아 채택은 여전히 가능 (HI-R01)
3. 오늘 남은 재시도는 없음 — 화면은 새 갈래로 바꾸는 것(MO)까지는 막지 않음

### (e) 다음 날 확인 (HI-R07)
1. 전날 카드를 채택했지만 확인은 안 하고 종료
2. 다음 날 정오 전: HI 목록에서 그 행이 "확인 안 됨" 상태로 보이고, 마감 전이므로 그 행에서 "이걸로 먹었다"를 탭해 확인 가능 (HI-R01의 적용 위치를 카드에서 목록으로 연장 — `[제안]`, 근거는 6절 미정 제안 참조)
3. 정오가 지나면 그 행의 확인 버튼은 사라지고 "확인 안 됨"으로 고정 (HI-R07, HI-R02) — "안 먹음"이 아니다
4. 같은 시각 오늘의 새 결정 계산은 (b)로 독립적으로 진행됨

## 3. 화면 목록

### DC — 결정 카드 (메인 화면)
- 답하는 질문: 오늘 저녁 나는 뭘 먹지?
- 입력: 0회(진입 시). 화면 안 탭만 있음 (DC-R04)
- 출력: 음식명, 갈래, 이유 한 줄 (DC-R02)
- 버튼: 미확정일 때 정확히 2개 — 거절 1개(RE-R01) + 확인 1개(HI-R01). 확정일 때 0개. 실패일 때 재시도 1개. 후보 0개일 때 "조건 고치기" 링크 1개
- 상태별 문구
  - 빈 값: 해당 없음 — DC-R04에 따라 열면 항상 계산을 시도하므로 "만들어진 적 없음" 상태 자체가 없다. 콜드스타트는 표본 부족으로 처리
  - 로딩: "고르는 중" (DC-R05)
  - 실패: "지금은 정해줄 수 없다" + 재시도 (DC-R06)
  - 후보 0개: "조건에 맞는 게 없다" + 걸린 조건별 개수 (DC-R07)
  - 표본 부족: "아직 취향을 모른다" (DC-R08)
  - 미확정: "오늘 저녁 추천" / 확정: "오늘은 <음식>으로 정했다" (DC-R09)

### MO — 갈래 전환 (DC 화면 안의 요소, 독립 화면 아님 — 전제 KK-OQ-01)
- 답하는 질문: 오늘은 어떤 방식으로 먹지, 바꿀 수 있나?
- 입력: 갈래 탭 1회 (MO-R04)
- 출력: 갈래 3개 표시, 활성 2개(해 먹기/나가서 먹기) + 비활성 1개
- 버튼: 갈래 칩 정확히 3개, 목록은 줄지 않음 (MO-R01)
- 상태별 문구
  - 빈 값·표본 부족·후보 0개: 해당 없음 — MO는 후보를 내지 않고 갈래만 바꾼다. 목록은 항상 3개 고정이라 비는 경우가 없다
  - 로딩·실패: DC와 공유(갈래 변경은 DC 재계산을 부른다, MO-R04)
  - 미확정: 해당 없음 — 기본 갈래가 항상 선택돼 있어 "선택 안 됨" 상태가 없다
  - 비활성 갈래: "아직 없음" (MO-R03)

### RE — 거절 사유 시트 (DC 화면 위 모달)
- 답하는 질문: 왜 이 음식은 아닌지 (선택) 알려줄래?
- 입력: 사유 탭 1회 또는 건너뛰기 탭 1회 (RE-R03)
- 출력: 화면이 즉시 새 결정으로 전환 (RE-R02)
- 버튼: 사유 4개 + 건너뛰기 1개, 총 5개 탭 옵션
- 상태별 문구
  - 빈 값·로딩·실패·후보 0개·표본 부족·미확정: 해당 없음 — 이 화면은 선택만 받고 계산·표시는 DC가 맡는다
  - 상한 도달: 거절 버튼 자리가 상한 문구로 바뀜 (RE-R05, 문구 `[제안]`)

### PR — 취향·제약
- 답하는 질문: 내 제약이 뭐고 어떻게 바꾸지?
- 입력: 5개 항목(PR-R01), 전부 건너뛸 수 있음(PR-R05), 필드 단위 즉시 반영 — 별도 "저장" 버튼은 요구사항에 없어 만들지 않음(6절 요구사항 제안)
- 출력: 현재 저장값
- 버튼: 항목별 입력 UI만 있고 확정 버튼은 없음(위 사유)
- 상태별 문구
  - 빈 값: "아직 입력 안 함" — "제약 없음"이 아니다 (PR-R03, PR-OQ-02)
  - 로딩·실패: 해당 없음 — 로컬 즉시 반영이라 이 상태 자체가 요구사항에 없다(6절 요구사항 제안 대상)
  - 후보 0개·표본 부족: 해당 없음 — PR은 후보를 만들지 않는다(DC가 만든다)
  - 미확정: 해당 없음 — "아직 입력 안 함"이 이 화면의 미확정에 해당하는 유일한 상태다

### HI — 먹은 기록
- 답하는 질문: 내가 실제로 언제 뭘 먹었지?
- 입력: 없음(열람). 삭제 탭(HI-R06), 마감 전 미확인 행의 확인 탭(HI-R01 연장, `[제안]`)
- 출력: 날짜, 음식, 갈래, 확인 여부 (HI-R03)
- 버튼: 행별 삭제 1개(HI-R06) + 마감 전 미확인 행에 한해 확인 1개
- 상태별 문구
  - 빈 값: "아직 기록이 없다" — "0회 먹음"이 아니다 (HI-R04)
  - 로딩·실패: 요구사항에 문구가 없음(6절 요구사항 제안)
  - 후보 0개: 해당 없음 — 목록은 필터링된 후보 개념이 없다
  - 표본 부족: 해당 없음 — 목록은 있는 그대로 보여줄 뿐 개인화 판정을 하지 않는다
  - 미확정: "확인 안 됨" — "안 먹음"이 아니다 (HI-R02, 6.6)
