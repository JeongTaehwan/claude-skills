## 1. 전제 — 화면이 갈리는 미정, 기획의 `추천:`대로 그린다

| 항목 | 가정(기획 추천) | 다른 답이면 무엇이 바뀌는가 |
|---|---|---|
| KK-OQ-01 | 사용자가 갈래를 고른다(IN-R02) | 앱이 정하면 IN의 갈래 칩이 사라지고 DC 헤더에 "오늘은 자동으로 <갈래>"가 새로 필요하다 |
| IN-OQ-01 | 주소는 기기 로컬에만, 동·읍·면 단위 | 서버 저장이면 "기기=데이터" 전제가 깨져 설정 화면에 계정 상태 표시가 필요해진다 |
| IN-OQ-02 | 예산·인분·주소 저장, 갈래는 매번, 순서 갈래→인분→예산→주소 | 갈래도 저장하면 IN 화면 자체가 생략되고 앱을 열면 바로 DC로 간다 |
| IN-OQ-03 | 기준 2인분·상한 6인분, 비례 환산 후 올림, 금액 10원 반올림 | 상한이 없으면 인분 칸이 자유 숫자가 되고 RC 표의 반올림 규칙도 다시 정해야 한다 |
| DC-OQ-05 | 후보 0개여도 제약을 풀지 않는다 | 풀면 DC-R07 문구 자체가 필요 없어지고 PR-R02("어떤 경우에도 제외")가 거짓이 된다 |
| DC-OQ-06 | 규칙 0개면 "아직 취향을 몰라서 오늘은 무작위로 골랐다" | "특별한 이유는 없다"쪽이면 표본 부족 문구(DC-R11)와 이유 줄이 한 화면에서 다른 말을 하게 된다 |
| DC-OQ-08 | 총액 재료비 합계 vs 입력 예산(총액), 허용폭 0 | 1인당 기준이면 카드가 예산÷인분을 새로 계산해 보여줘야 하고 IN의 예산 문구도 바뀐다 |
| RE-OQ-02 | 다시 돌리기 상한 없음 | 상한을 두면 RE 버튼에 상한 도달 상태·문구가 새로 필요하다 |
| PR-OQ-02 | 미입력은 "아직 모름"(3상태) | "없음"이면 콜드스타트 안내 한 줄이 불필요해지나 안전 리스크는 그대로 남는다 |
| HI-OQ-01 | 확인 탭 + 레시피 1회 이상 열람 | 확인 탭만이면 RC 열람 추적 이유가 사라지고 S3만으로 대신해야 한다 |
| HI-OQ-02 | 카드에 나온 것 전부, 창 = 레시피 개수의 절반 | 확인된 것만 넣으면 미확인 채 리롤된 음식이 바로 다음 카드에 또 나올 수 있다 |
| HI-OQ-03 | (기획 추천 없음, UX 가정) 확인 버튼은 DC/MO 카드 + 다음 날 정오까지 HI 목록 행에도 있다 | HI 목록에만 두면 HI-R01("결정 카드에... 확인 버튼")과 문구가 어긋난다 |
| MO-OQ-03 | 매장 필터 미구현, 배달 메뉴 목록에서 무작위 | 매장 데이터가 생기면 MO에 매장명·실제 배달 가능 여부가 추가되고 "못 거른다" 문구가 사라진다 |
| MO-OQ-04 | 메뉴명 클립보드 복사 + 배달앱 열기 | 딥링크 방식이면 실패(앱 미설치 등) 시 별도 실패 문구가 필요해진다 |
| CA-OQ-01 | 고정 단가표, 기준일 90일 경과 시 "추정" | 실시간 API면 CA-R01(우리 소유 데이터)이 깨지고 RC에 "지금 가격"이라는 새 상태가 생긴다 |
| CA-OQ-02 | 레시피 20개, 사람이 최종 검수 | 개수가 적으면 반복 회피 창이 짧아지고 DC-R07(후보 0개)이 훨씬 자주 뜨는 화면이 된다 |
| RC-OQ-01 | 손질~완성 총시간 + 대기시간 별도, 난이도 없음 | 손질 제외 시간만 쓰면 표시 시간과 실제 시간이 달라 "만들 여력" 판단에 못 쓴다 |

## 2. 핵심 흐름

### (a) 첫 실행 (프로필·기록 0)
1. 앱 실행 → IN 화면, 모든 칸 "아직 입력 안 함"(IN-R09), 갈래는 "해 먹기" 기본 선택(MO-R02)
2. 갈래·예산·인분 입력. 시켜 먹기를 고르면 주소 칸이 나타남(IN-R03), 건너뛰기 가능(IN-R12)
3. "돌리기" 탭 — 세 값이 다 있어야 계산이 시작된다(IN-R01)
4. 로딩 "고르는 중"(DC-R05) → 결과 도착 즉시 3절 애니메이션(DC-R04)
5. 카드 등장: 확인된 기록이 없어 "아직 취향을 모른다"(DC-R11), 이유 줄은 예산·인분 근거가 있으면 그 내용, 없으면 DC-OQ-06 추천 문구
6. 해 먹기면 "레시피 보기"가 있다(DC-R10)

### (b) 평소 저녁
1. 앱 열기 → IN 화면, 예산·인분·주소는 "지난번 값"으로 채워짐(IN-R07·R08), 갈래는 매번 새로 고름
2. 필요하면 그 자리에서 값 수정 → "돌리기" 탭
3. 로딩 → 카드 등장(3절 애니메이션)
4. 해 먹기: "레시피 보기" → RC에서 재료 표·조리 단계 확인(RC-R02·R06)
5. RC에서 뒤로 가면 DC 카드로 복귀, "이걸로 먹었다" 탭(HI-R01) → HI에 미확인 상태로 기록 생성(HI-R02)

### (c) 다시 돌리기 반복
1. 카드가 마음에 안 들면 "다시 돌리기"(RE-R01) 탭 → 즉시 재계산, 같은 자리에 같은 애니메이션(RE-R02)
2. 갈래·예산·인분은 그대로 유지, 다시 묻지 않음(RE-R05), 사유도 묻지 않음(RE-R06)
3. 방금 본 음식은 바로 다음엔 안 나옴(RE-R03), 창은 HI-OQ-02 추천을 따름
4. 상한 없음(RE-OQ-02 추천) — 원하는 만큼 반복 가능
5. `[제안]` "이걸로 먹었다"를 이미 탭한 뒤에도 "다시 돌리기"는 계속 눌린다 — RE-R04가 상한을 말하지 않고 HI-R01도 카드를 잠근다고 말하지 않는다. 리롤하면 새 카드는 미확인 상태로 시작하고, 이전 확인 기록은 HI에 그대로 남는다(7절 미정 제안 1번)

### (d) 시켜 먹기 (가벼운 흐름)
1. IN에서 갈래 = 시켜 먹기(MO-R01), 주소는 선택 입력(IN-R12)
2. 계산·애니메이션은 해 먹기와 동일(DC-R04·R05 공유)
3. 결과는 MO 형태: 메뉴명 + 예상 가격대(MO-R04·R06) — 레시피 링크 없음, "레시피는 없어요" 안내(MO-R09)
4. 주소 없으면 "주소를 아직 몰라요", 있어도 "주소로 매장을 걸러주지는 못해요"(MO-R07, 6.9)
5. "배달앱에서 찾기" → 메뉴명 복사 + 배달앱 열기(MO-OQ-04 추천)
6. "다시 돌리기"·"이걸로 먹었다"는 해 먹기와 동일하게 동작

### (e) 후보 0개 / 예산 초과
1. 후보 0개(계산 성공, 남은 후보 없음): "조건에 맞는 게 없다" + 조건별 걸러진 개수(DC-R07), 제약은 풀지 않는다(DC-OQ-05 추천) → "조건 고치기" 링크로 설정行
2. 실패(계산 자체 실패)는 다른 문구: "지금은 정해줄 수 없다" + 재시도(DC-R06) — 후보 0개와 절대 같은 말을 쓰지 않는다
3. 예산 초과: 후보는 정상적으로 나오고 카드에 "예산 초과"만 더 붙는다(DC-R08) — 카드 자체를 막지 않는다(PR-R03)
4. 예산 미입력이면 판정 문구를 아예 안 쓰고 금액만 표시(IN-R10)
5. 단가에 추정이 섞이면 금액 옆에 "추정"(DC-R09) — 후보 0개·예산 판정과 별개로 항상 함께 뜬다

### (f) 기록·확인
1. "이걸로 먹었다" 탭 → HI에 미확인 상태로 즉시 기록(HI-R01·R02)
2. 다음 날 정오까지 HI 목록의 그 행에서도 확인 가능(HI-OQ-03 UX 가정) — 그날의 카드 자체는 새 IN/DC 세션으로 대체돼 사라지므로 목록이 유일한 접근 경로
3. 정오가 지나면 확인 버튼이 사라지고 "확인 안 됨"으로 고정(HI-R07·R02) — "안 먹음"이 아니다
4. 목록은 날짜·음식·갈래·인분·금액·확인 여부를 보여준다(HI-R03), 행별 삭제 가능(HI-R06)
5. 기록 0건이면 "아직 기록이 없다"(HI-R04)

## 3. 가운데 등장 애니메이션 명세 (DC-R04, RE-R02)

**"딱! 뜨게" 해석**: 사람의 "딱!"을 카드가 스며들듯 나타나는 것이 아니라 한 순간에 눈에 띄게 정지·확정되는 것으로 읽었다 — 페이드만으로는 "딱"의 정지감이 안 난다.

**트리거**: "돌리기"(첫 생성) 또는 "다시 돌리기"(RE) 탭 → 결과 데이터가 준비된 시점부터 시작. 로딩 중엔 "고르는 중"만 보이고 직전 카드는 완전히 비운다(DC-R05).

**형태 `[제안]`: 슬롯-사이클링 → 스프링 착지.** 이유: 답5 한 문장이 "다시 랜덤 돌리기"(과정)와 "딱! 뜨게"(순간)를 둘 다 요구한다. 순수 스케일·페이드 스프링만으로는 "돌리기"라는 무작위성의 체감이 없고, 순수 슬롯 사이클링만으로는 "딱" 하는 정지의 쾌감이 없다.

| 단계 | 길이 | 동작 |
|---|---|---|
| 0 로딩 | 가변 `[추정]` 200~600ms | "고르는 중", 이전 카드 요소 전부 비움 |
| 1 사이클링(슬롯) | 360ms | 카드 중앙에 음식명이 6회 정도 빠르게 바뀐다(교체 간격 60→70→90→120→160→220ms로 점점 느려짐). 금액·이유줄·버튼은 아직 안 보임 |
| 2 착지(스프링) | 220ms | 텍스트가 최종 음식명에서 멈추는 순간 카드가 scale 0.92→1.04→1.00, opacity 0→1로 오버슈트 이동 — "딱"의 순간 |
| 3 디테일 페이드인 | 120ms(2단계와 50ms 겹침) | 이유 줄·인분·금액·버튼이 순서대로 살짝 아래에서 제자리로 페이드인 |
| 합계(로딩 제외) | **상한 700ms** `[제안]` | 계산이 오래 걸려도 1~3단계는 700ms를 넘지 않는다 |

**버튼 비활성**: 1단계 시작부터 3단계 끝까지 모든 버튼(다시 돌리기·이걸로 먹었다·레시피 보기·배달앱에서 찾기·갈래 칩)이 비활성. 흐리게(dimmed) 표시하고 탭해도 반응하지 않는다. 3단계가 끝나는 정확한 시점에 살아난다(DC-R04).

**`prefers-reduced-motion` 대체**: 1단계(사이클링) 생략, 2단계는 스케일 없이 150ms 단순 페이드(opacity 0→1)만, 3단계 생략(모든 요소 동시 등장) — 총 길이 150ms, 버튼 비활성 구간도 150ms로 줄어든다.

**연속 돌리기 중첩 처리**: 재생 중엔 버튼이 비활성이라 재요청 자체가 막힌다. 3단계 종료 직후 바로 다시 누르면 진행 중이던 트랜지션을 즉시 취소하고 카드 내용을 전부 비운 뒤 0단계부터 새로 시작한다 — 이전 애니메이션 잔상이 새 카드에 겹치지 않도록 카드 컴포넌트를 매번 새로 그린다(예: 프레임워크의 key 교체) `[제안]`.

**햅틱 `[제안]`**: 2단계(착지) 시작 시점에 짧은 임팩트 햅틱(약 20~30ms) 1회. "딱!"이라는 의성어의 촉각적 뉘앙스에 대응한다. 플랫폼이 지원하지 않으면 조용히 생략하고 에러를 내지 않는다 — 실제 지원 여부는 `[미정 KK-OQ-03]`(플랫폼)에 달려 있다.

## 4. 화면 목록

### IN — 입력
- 답하는 질문: 오늘은 얼마로 몇 인분을 어떻게(해 먹기/시켜 먹기) 해결할까?
- 입력: 갈래(2택1, IN-R02) · 예산(원, IN-R04) · 인분(1 이상 정수, IN-R05) · 주소(시켜 먹기 선택 시만, 건너뛰기 가능, IN-R03·R12) — 한 화면(IN-R06)
- 출력: 각 칸에 지난번 값이 채워져 있음(IN-R07·R08)
- 버튼: 갈래 칩 2개(MO-R01) + 돌리기 1개 + (시켜 먹기 시) 주소 건너뛰기 1개
- 상태: 빈 값 "아직 입력 안 함"(IN-R09) · 로딩/실패/후보 0개/표본 부족: 해당 없음(IN은 계산하지 않는다) · 미확정: 해당 없음(갈래 기본값 항상 선택, MO-R02) · 단가 추정: 해당 없음 · **주소 미입력**: "주소를 아직 몰라요"(6.9) · 예산 초과: 해당 없음(판정은 DC가 한다)

### DC — 결정 카드
- 답하는 질문: 지금 뽑은 오늘의 하나는 뭐고 얼마지?
- 입력: 0회(직전 IN에서 받음), 화면 안 탭만
- 출력(해 먹기): 음식명·갈래·이유 한 줄·인분·금액=재료비 합계(DC-R02), 예산 판정(입력 시)
- 버튼: 다시 돌리기(RE-R01) + 이걸로 먹었다(HI-R01) + 레시피 보기(DC-R10) = 3개. 실패 시 재시도 1개. 후보 0개 시 조건 고치기 1개
- 상태: 빈 값: 해당 없음(IN 완료 즉시 계산, DC-R01) · 로딩 "고르는 중"(DC-R05) · 실패 "지금은 정해줄 수 없다"+재시도(DC-R06) · 후보 0개 "조건에 맞는 게 없다"+조건별 개수(DC-R07, DC-OQ-05 추천) · 표본 부족 "아직 취향을 모른다"(DC-R11) · 미확정: 이유 줄이 DC-OQ-06 추천 문구 · **단가 추정**: 금액 옆 "추정"(DC-R09) · 주소 미입력: 해당 없음(DC엔 주소 자체가 없음, IN-R11) · **예산 초과**: "예산 <금액> 초과"(DC-R08, DC-OQ-08 추천)

### RC — 레시피·조리법 (레시피 상세)
- 답하는 질문: 이걸 몇 인분, 뭘로, 어떻게 만들지?
- 입력: 0회(열람). 인분은 IN 값이 이미 반영됨(RC-R03)
- 출력: 재료 표(재료명·수량·단가·소계, RC-R02), 합계 = DC 카드 금액과 동일(RC-R04), 조리 단계 번호 목록(RC-R06), 조리 시간(분, RC-OQ-01 추천), "없는 재료는 사야 한다"는 안내(RC-R10)
- 버튼: 뒤로 가기 1개. `[제안]`(HI-OQ-03 UX 가정) 확인 버튼은 여기 없음 — DC 카드로 돌아가야 확인할 수 있다(7절 미정 제안 2번)
- 상태: 빈 값/로딩/실패/후보 0개/표본 부족/미확정: 해당 없음 — DC-R10 경로로만 진입하고 레시피 없는 음식은 후보 자체가 아니다(RC-R01, CA-R02) · **단가 추정**: 재료별 행에 "추정"(RC-R05), 하나라도 있으면 합계도 추정 · 주소 미입력/예산 초과: 해당 없음(RC는 판정하지 않는다)

### MO — 시켜 먹기 (DC 카드의 갈래=시켜 먹기 형태)
- 답하는 질문: 오늘은 뭘 시켜 먹고, 대략 얼마고, 어떻게 주문하지?
- 입력: 0회(직전 IN에서 갈래·주소 이미 받음)
- 출력: 메뉴명·갈래·이유 한 줄·인분·예상 가격대(MO-R04·R06), 매장 필터 안내
- 버튼: 다시 돌리기 + 이걸로 먹었다 + 배달앱에서 찾기(MO-R04, MO-OQ-04 추천) = 3개. 로딩/실패/후보 0개는 DC와 화면·문구 공유
- 상태: 로딩/실패/후보 0개/표본 부족은 DC와 동일 · 단가 추정: 해당 없음 — "예상 가격대" 자체가 이미 추정성을 명시하므로 별도 "추정" 배지는 붙이지 않는다 `[제안]` · **주소 미입력**: "주소를 아직 몰라요"(6.9) · **매장 필터 없음**: "주소로 매장을 걸러주지는 못해요"(MO-R07, 6.9) · 예산 초과: 해당 없음(MO-R06이 가격대로만 안내, DC-OQ-08은 재료비 기준이라 시켜 먹기엔 적용 안 됨 `[제안]`)

### PR / 설정 — 취향·제약과 기본값
- 답하는 질문: 내 제약·기본값이 뭐고 어떻게 바꾸지?
- 입력: 절대 제외·싫어하는 것·기본 예산·기본 인분·집주소 5가지(PR-R01), 전부 건너뛸 수 있음(PR-R06), 필드 단위 즉시 반영
- 출력: 현재 저장값. 나머지는 요구사항이 없어 이 문서는 만들지 않는다(7절 요구사항 제안)
- 버튼: 항목별 입력 UI만, 확정 버튼 없음(즉시 저장이므로)
- 상태: 빈 값 "아직 입력 안 함"(PR-R04, PR-OQ-02 추천) · 로딩/실패: 해당 없음(요구사항에 문구 없음, 7절 요구사항 제안) · 후보 0개/표본 부족/미확정: 해당 없음(PR은 후보를 만들지 않는다) · 단가 추정/예산 초과: 해당 없음(PR은 판정하지 않는다) · **주소 미입력**: "아직 입력 안 함"(다른 화면과 같은 빈 값 문구)
- `[제안]` 설정은 PR과 같은 데이터를 보여주는 진입점이다. 별도 화면을 만들지 않는다 — 만들면 요구사항에 없는 화면 요소가 된다(7절 요구사항 제안)

### HI — 먹은 기록
- 답하는 질문: 내가 실제로 언제 뭘 먹었지?
- 입력: 없음(열람). 삭제 탭(HI-R06), 마감 전 미확인 행의 확인 탭(HI-R01 연장, HI-OQ-03 UX 가정)
- 출력: 날짜·음식·갈래·인분·금액·확인 여부(HI-R03)
- 버튼: 행별 삭제 1개 + 마감 전 미확인 행에 한해 확인 1개
- 상태: 빈 값 "아직 기록이 없다"(HI-R04) · 로딩/실패: 요구사항 없음(7절 요구사항 제안) · 후보 0개/표본 부족: 해당 없음(목록은 필터·개인화 판정을 하지 않는다) · **미확정**: "확인 안 됨"(HI-R02, 6.9) · 단가 추정: 원 기록의 추정 표시를 그대로 보여줌(DC-R09 상속) `[제안]` · 주소 미입력/예산 초과: 해당 없음

### 재료비 표기 형식 `[제안]`

- 확정 금액: 천 단위 콤마 + "원" — `8,200원`. 10원 단위 반올림(IN-OQ-03 추천).
- 추정이 섞인 금액: 접두어 "약" + 접미어 "· 추정" — `약 8,200원 · 추정`. 확정이면 접두어 없이 그냥 `8,200원`.
- 시켜 먹기 예상 가격대: 범위 + "대" — `12,000~15,000원대`. "가격"이 아니라 "가격대"로 쓴다(MO-R06).
- 예산 초과 문구: 금액 뒤에 "초과" — `예산 15,000원 초과`(DC-OQ-08 총액 비교 추천 반영).
- 재료 표의 단가·소계도 같은 규칙을 쓰되 칸이 좁으면 "추정"을 접미어로만 축약(예: `150원 추정`).
