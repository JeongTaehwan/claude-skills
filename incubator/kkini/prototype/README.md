## 2. 여는 법

```
# ① 파일을 그냥 열기 — file:// 로도 동작한다
open prototype/index.html        # 또는 파일 더블클릭

# ② 로컬 서버 (권장 — 폰트·localStorage가 브라우저 설정에 덜 좌우된다)
cd prototype && python3 -m http.server 8000
# → http://localhost:8000
```

빌드 없음. 설치 없음. 파일 3개(`index.html`, `catalog.js`, `README.md`)뿐이다.
오프라인이면 Google Fonts가 실패하고 폴백 서체(`Apple SD Gothic Neo` / `Malgun Gothic`)로 그대로 뜬다.

### 한 바퀴 둘러보는 순서

1. 열면 바로 카드가 있다 (입력 0회). 이유 줄은 `아직 취향을 모른다 …` — 진짜 콜드 스타트다.
2. `다시 뽑기` → 사유 4종 + 건너뛰기 → 즉시 다른 음식. 5번 하면 거절 버튼 자리가 상한 문구로 바뀐다.
3. `이걸로 먹었다` → 헤더가 `오늘은 <음식>으로 정했다`로 바뀌고 버튼이 사라진다. 새로고침해도 그대로다.
4. `나가서 먹기`로 바꾸면 재계산되고 재료 전제 한 줄이 사라진다.
5. 설정 → `예시 기록 7건 넣기` → 기록 탭에 7건(확인됨 5 / 확인 안 됨 2).
   그 뒤 설정 → `오늘 초기화` → 오늘 카드를 다시 뽑으면 개인화된 이유 줄(확인 3건 이상)이 나온다.
6. 설정 → 절대 제외 `있음`에서 14종을 다 고르고 `오늘 초기화` → 후보 0개 화면.
7. 설정 → `실패 상태 미리보기` → `지금은 정해줄 수 없다` + 재시도.

### 요구사항에서 의도적으로 벗어난 점

요구사항·flows에 근거가 없는데 넣은 것들이다. 지워야 할지는 사람이 정한다.

1. **확정 카드에도 이유 줄을 남겼다.** `ux/flows.md` 4절 "DC — 확정됨" 와이어프레임은 음식명·갈래만 그리는데, DC-R02는 "셋 중 하나라도 없으면 카드를 띄우지 않는다"다. DC-R02를 따랐다.
2. **확정 뒤에는 갈래 세그먼트를 비활성화했다.** MO-R04("갈래를 바꾸면 재계산")와 flows (c)("확정 상태에서는 조작 대상이 없다")가 부딪힌다. 근거 없는 임의 처리다 (→ 6절 ③).
3. **저장 실패 배너 한 줄**(`저장이 되지 않는다 — 이 화면은 보이지만 기록은 남지 않는다`)을 새로 썼다. KK-OQ-07이 요구하는 여섯 번째 상태의 자리표다.
4. **개발용 버튼 3개**와 설정 화면 하단의 상수 표시 줄. 정식 구현에는 없다.
5. **상단바의 날짜 표시**, 확정 카드의 `오늘 결정은 끝났다 …` 한 줄, 기록 화면 하단의 확인 기한 안내 한 줄. 문구 표에 없어 새로 썼고, 어미는 평서체로 맞췄다.
6. **예산 등급 → 원화 환산표**(1=9,000원 / 2=16,000원 / 3=28,000원)를 임의로 정했다 (→ 6절 ⑦).

## 6. 구현 중 발견한 미정

문서에 답이 없어서 프로토타입이 임의로 메운 지점이다. **전부 사람이 정해야 한다.**
`docs/open-questions.md`에 넣을지는 서기·PM이 판단한다 — 이 파일에서 옮기지 않았다.

1. **DC-OQ-06이 여전히 열려 있다.** 확인 기록 3건 미만 + 맥락 규칙 1개 이상일 때 `아직 취향을 모른다`와 `요즘 계절에 맞는 걸로 골랐다` 중 무엇을 쓰는지 문서에 답이 없다. 프로토타입은 **두 줄로 쌓아** 둘 다 보여주는 방식으로 피했다 — 이건 결정이 아니라 회피다. 이유 줄이 두 줄이어도 되는지부터 정해야 한다 (DC-R02는 "한 줄"이라고 쓴다).
2. **확정 카드에 이유 줄을 남기는가.** DC-R02(3요소 필수) ↔ flows 와이어프레임(확정 카드에 이유 없음). 둘 중 하나가 틀렸다.
3. **확정한 뒤 갈래를 바꿀 수 있는가.** 바꿀 수 있다면 이미 채택된 결정은 어떻게 되는가(HI-OQ-06 취소 수단과 맞물린다). 바꿀 수 없다면 MO-R04에 그 예외를 적어야 한다.
4. **"하루 1건"은 날짜당 1건인가, (날짜 × 갈래)당 1건인가.** C1은 "하루 저녁 1건"인데 MO-R04는 갈래별 재계산을 요구한다. 프로토타입은 `(날짜, 갈래)` 키로 저장해서 갈래를 오가면 각각 같은 카드가 돌아온다 — 즉 하루에 `proposed` 결정 레코드가 2건 생길 수 있다(채택은 1건만 가능). 북극성 분모가 이걸 허용하는지 정해야 한다.
5. **"싫어하는 것"의 단위가 없다.** architecture 4.2는 음식 id 집합으로 쓰고, PR 화면에는 입력 UI 형태가 없다. 프로토타입은 **태그 다중 선택**으로 했다. 태그 단위면 "면" 하나를 고르는 순간 감점 대상이 30종을 넘어 -40점이 실질적 제외로 작동한다 — 감점 폭도 다시 봐야 한다.
6. **거절 사유 4종 중 3종이 어디에도 쓰이지 않는다.** architecture 4.2는 `reason='dislike'`만 감점에 쓴다. `not_today` / `ate_recently` / `cannot_cook_now`는 기록만 되고 계산에 안 들어간다. 사유를 물어 놓고 쓰지 않는 것이 의도인지 확인이 필요하다 (RE-R03은 수집만 규정한다).
7. **`budgetTier` → 원화 환산표가 없다.** architecture는 "원화 금액을 카탈로그에 박지 않는다"만 말하고 `budgetFits()`의 정의가 없다. 프로토타입은 등급 상한을 9,000 / 16,000 / 28,000원으로 임의 지정했다. 이 표가 없으면 "1인 예산 15,000원 이하라서 골랐다"(flows 이유 줄 예시)를 검증할 수 없다.
8. **`partySize`는 수집만 되고 계산에 안 쓰인다** (리뷰 #10). 프로토타입은 화면에 그 사실을 적었다(`저장만 된다 — 오늘의 결정 계산은 이 값을 읽지 않는다`). 인원이 결정에 영향을 줘야 하는지, 아니면 PR-R01에서 빼야 하는지 정해야 한다.
9. **"저녁 16~23시"가 하는 일이 없다.** KK-OQ-05 추천에 시간 창이 있는데 로직에서 그 창을 읽는 곳이 없다(늦은 시각 가점은 `hour >= 21`을 쓴다). 15시에 열면 무엇을 보여줄지, 02시(하루 경계 전)에 열면 "어제 저녁"을 보여줄지 요구사항에 없다.
10. **카탈로그 로드 실패 상태가 6.6에 없다.** `catalog.js`가 없으면 후보가 0개라서 화면이 "조건에 맞는 게 없다"를 쓰는데, 이건 조건 문제가 아니라 실패다. 6.6의 6종 중 어디에도 안 맞는다.
11. **HI 목록의 확인 버튼 라벨이 카드의 채택 버튼과 같다.** 둘 다 `이걸로 먹었다`인데 카드의 그것은 **채택**(기록 생성)이고 목록의 그것은 **확인**(섭취 확정)이다. 같은 문구가 다른 두 동작을 가리킨다 — HI-OQ-04(라벨)와는 다른 문제다.
12. **`Answered<T>`의 "없음"을 화면이 어떻게 읽는가.** 절대 제외를 `없음`으로 선언하면 필터가 0개를 거르고 `blockedBy.absolute = 0`이 된다. 후보 0개 화면에서 `절대 제외에 걸림 0개`는 "선언 안 함"과 구분되지 않는다. 3상태를 화면 숫자까지 끌고 갈지 정해야 한다.
13. **거절 상한 도달 뒤 갈래를 바꾸면 거절 예산이 되살아나는가.** flows (d)3은 "갈래 전환까지는 막지 않는다"만 적는다. 프로토타입은 거절 횟수를 날짜 단위로 세므로 갈래를 바꿔도 상한은 그대로다 — 이 해석이 맞는지 문서에 없다.
