# 끼니 v1 — Expo(React Native) 프로토타입

> **정식 구현이 아니다.** `docs/requirements.md`는 **v1 미승인 초안(2026-09-12)**이다.
> 사람이 v0를 보고 "이게 아니라"라고 해서 제품 정의가 다시 쓰였고, 이 폴더는 그 v1 문서를
> `docs/open-questions.md`의 `추천:` 답을 전제로 화면까지 옮긴 **클릭 가능 프로토타입**이다.
> 게이트 A(요구사항 승인 + BLOCKER 0건)는 통과하지 않았다 — 이걸 구현 착수로 세지 않는다.
> **레시피 본문·재료 단가·알레르겐 태그는 전부 사람 검수 전 초안이다. 그대로 조리하지 마라.**

## 폰에서 보는 법 (v0와 같다)

```
cd incubator/kkini/prototype-expo && npm install && npx expo start
```

터미널 QR을 **iOS는 기본 카메라**, **Android는 Expo Go 앱 스캐너**로 읽는다.
폰과 PC가 같은 Wi-Fi가 아니면 `npx expo start --tunnel`. 첫 로딩에 한글 폰트 25MB를 받는다.

> 이 세션에서는 `expo.dev`·`exp.host`가 403이라 `expo start`·로그인·EAS·Snack을 실행하지 않았다.
> 검증은 `npx expo export --platform web` + 그 `dist/`를 띄운 Playwright로 했다.

## 3. "검수 전 초안" 배지의 뜻

카드와 레시피 화면에 항상 붙는다. 뜻은 하나다 — **이 레시피 본문·재료량·알레르겐 태그를 사람이 확인하지 않았다.**

- RC-R08은 "생성 모델이 쓴 본문을 사람 검수 없이 싣지 않는다"고 요구한다. 이 프로토타입은 그 요구를 **어긴 상태**이고, 배지는 그 사실을 숨기지 않으려고 붙인 것이다.
- RC-R09는 "검수되지 않은 레시피는 후보에 들어가지 않는다"고 한다. 20개가 전부 `reviewedAt: null`이므로 이 규칙을 지키면 **후보가 0개가 되어 앱이 아무것도 못 한다.** 그래서 프로토타입은 후보에 넣고 배지를 띄우는 쪽을 골랐다 (아래 편차 ①).
- `allergens` 태그가 틀리면 PR-R02("어떤 경우에도 제외")가 거짓이 된다 — 안전 문제다. 사람 검수(그리고 `PR-OQ-05`대로 작성자와 다른 주체의 교차 검수)가 끝나면 `reviewedAt`에 날짜를 넣고, 필터 1단계에서 `reviewedAt` 없는 레시피를 빼면 된다(`draw()`의 주석 위치).

## 5. 편차 — 문서와 다르게 구현한 것

사람이 지울지 정한다. 전부 근거를 적었다.

1. **RC-R09를 지키지 않는다.** 검수 전 레시피를 후보에 넣는다. 지키면 후보가 0개다(3절). 대신 배지를 항상 띄우고, 필터 1단계 주석에 되돌리는 방법을 적어 두었다.
2. **애니메이션 1단계 길이.** ux 3절의 세 숫자가 서로 안 맞는다 — "1단계 360ms" / 교체 간격 목록 `60→70→90→120→160→220`(합 720ms) / "합계 상한 700ms". 프로토타입은 **표가 정의한 단계 길이와 700ms 상한**을 지키는 쪽을 골라 교체 간격을 `60→70→90→120`(340ms)으로 자르고, `220`은 같은 표가 2단계(착지)로 정의한 값이라 착지에 썼다. **`160`은 쓰지 않았다.** 실측 1~3단계 630ms, 0단계 로딩 200ms 포함 852ms.
3. **시켜 먹기에는 예산 판정과 추정 배지를 쓰지 않는다.** ux 4절 MO가 "해당 없음"이라고 못 박아서다. DC-R08("예산이 입력돼 있으면 카드는 둘 중 하나를 쓴다")과 어긋난다 → 미정 ①. 내부 가중치는 architecture 4.5대로 가격대 하단으로 판정해 감점에만 쓴다.
4. **기준 인분에서는 `ceilPractical`을 적용하지 않는다.** 적용하면 작성자가 쓴 "두부 1/2개"가 2인분(=기준)에서 1개로 올라가 화면 수량이 레시피 본문과 달라지고 금액이 부푼다. 인분이 기준과 다를 때만 올림한다 → 미정 ⑥.
5. **주소 "건너뛰기" 버튼을 만들지 않았다.** IN-R12가 `시켜 먹기에서 필수 입력`으로 바뀌어(사람 원문 "시켜먹는 건 집주소 입력 필요") 주소가 비면 "돌리기"가 비활성이고 6.9의 "주소를 아직 몰라요"가 뜬다. 그런데 `ux/flows.md` 4절 IN은 아직 "주소 건너뛰기 1개"를 버튼 목록에 두고 2(d)1도 "주소는 선택 입력"이라고 쓴다 — **UX 문서가 갱신 전이다**(→ 미정 ⑪). 주소가 있어도 매장 필터는 동작하지 않고(MO-R07) 그 사실은 카드가 쓴다. 지우는 수단은 설정 화면의 "주소 지우기"뿐이고, 지우면 시켜 먹기는 다시 돌릴 수 없다(PR-R07 ↔ IN-R12).
6. **검증 스크립트에 zod를 쓰지 않았다.** architecture 7.2가 zod를 지정했지만 의존성을 늘리지 않으려고 손으로 쓴 검사로 대체했다. 막는 항목(①~⑥)은 같다.
7. **메뉴명 클립보드 복사(MO-OQ-04 추천)를 구현하지 않았다.** `expo-clipboard` 의존성이 필요하고 질문이 LATER다. 배달앱 웹 URL만 연다(`https://www.baemin.com`, architecture 6절: 비공식 스킴 금지).
8. **탭을 옮기면 오늘 화면이 입력 단계로 돌아간다.** 카드가 사라진다. ux (f)2("그날의 카드는 새 세션으로 대체돼 사라진다")와 같은 방향이지만 요구사항에 명시된 동작은 아니다.
9. **`SafeAreaView`는 `react-native`의 것을 쓴다** — RN 0.86에서 deprecated이고 콘솔에 warnOnce가 한 번 뜬다. 권장 대체(`react-native-safe-area-context`)는 의존성이 하나 늘어난다.
10. **단가·환산 계수는 전부 `isEstimate: true`다.** 시세를 조사한 값이 아니라 감으로 적었다. 그래서 모든 해 먹기 금액에 "추정"이 붙는다 — 이건 편차가 아니라 CA-R03을 지킨 결과다.

## 7. 구현 중 발견한 미정

v1 문서에 답이 없어 프로토타입이 임의로 메운 지점이다. **전부 사람이 정해야 한다.**

1. **시켜 먹기에 예산 판정을 쓰는가.** DC-R08은 "예산이 있으면 둘 중 하나를 쓴다"고 하고 ux 4절 MO는 "해당 없음"이라고 한다. 지금은 ux를 따라 판정을 감췄다 — 사용자는 32,000~48,000원대가 예산 15,000원을 넘는다는 말을 카드에서 못 듣는다.
2. **시켜 먹기의 가격대는 인분에 비례하는가.** MO-R06은 "1인 기준 예상 가격대"라고만 한다. 프로토타입은 `가격대 × 인분`으로 곱해 보여준다(2인분 → 32,000~48,000원대). 치킨 한 마리를 2인이 나눠 먹는 경우엔 틀린 곱셈이다.
3. **`검수 전 초안` 배지의 문구·존재가 요구사항에 없다.** 3절의 이유로 넣었지만 6.9 상태 어휘에 그 상태가 없다. "검수 전"은 빈 값도 실패도 추정도 아니다 — 일곱 번째 상태가 필요할 수 있다.
4. **DC-OQ-06의 전제가 약해졌다.** architecture 5.4가 예고한 대로 v1은 이유 줄이 비는 경우가 없어 "아직 취향을 몰라서 오늘은 무작위로 골랐다"가 **한 번도 안 나온다**. 이 문구를 지울지, 어떤 조건에서 쓸지 정해야 한다.
5. **"지난번 값"(IN-R07)과 "기본 예산·기본 인분"(PR-R01)이 두 곳에 따로 저장된다.** 프로토타입은 입력 화면이 `lastInputs`를, 설정이 `profile.default*`를 쓰고 **입력 화면이 이긴다.** 설정에서 기본값을 고쳐도 다음에 입력 화면에는 지난번 값이 뜬다 — ux 7절이 이미 BLOCKER로 올린 질문이다.
6. **인분 환산의 반올림 지점.** 편차 ④의 처리(기준 인분에서는 올림 안 함)는 IN-OQ-03 추천에 없는 규칙이다. 3인분에서는 "두부 0.75개 → 1개"로 올라가 2인분보다 재료비가 40% 이상 튈 수 있다.
7. **양념을 "쓴 만큼"으로 계산한 금액을 사용자가 어떻게 읽는가.** architecture 4.4가 대가로 지적한 그대로다 — 빈 주방이면 실제 결제액이 훨씬 크다. 프로토타입은 레시피 화면에 한 줄로 적었지만, 카드의 "약 5,980원"만 본 사람에게는 그 경고가 닿지 않는다.
8. **조리 시간 vs 시각 가중치(architecture 5.2 마지막 줄)가 사람이 말하지 않은 축이다.** 20시 이후 40분 초과 레시피를 절반으로 깎는다. 코드에서 한 줄로 격리해 두었으니 빼려면 그 줄만 지우면 된다.
9. **애니메이션 재생 중 앱이 백그라운드로 갔다 오면?** ux 7절이 LATER로 올린 질문이고 프로토타입은 아무 처리도 하지 않는다 — 타이머가 그대로 돌아 착지가 이미 끝나 있을 수 있다.
10. **"이걸로 먹었다"를 누른 뒤에도 다시 돌리기가 계속 눌린다.** ux 2(c)5의 `[제안]`을 따랐다. 그러면 하루에 확인 기록이 여러 건 쌓일 수 있는데 C1("하루 저녁 1건")이 그걸 어떻게 세는지가 없다 (ux 7절 BLOCKER).
11. **IN-R12(주소 필수)와 PR-R07(주소는 언제든 지울 수 있다)이 부딪힌다.** 설정에서 주소를 지우면 시켜 먹기 갈래는 돌릴 수 없는 상태가 된다. 그때 사용자를 입력 화면으로 보낼지, 해 먹기로 갈래를 되돌릴지가 문서에 없다. `ux/flows.md` 4절 IN의 "주소 건너뛰기" 버튼과 2(d)1의 "주소는 선택 입력"도 함께 갱신돼야 한다.
