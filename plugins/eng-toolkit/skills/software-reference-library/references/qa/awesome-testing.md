# Awesome Testing (TheJambo)

https://github.com/TheJambo/awesome-testing

## 한 줄
도구 목록이 아니라 테스트를 **어떻게 생각할지**에 관한 자료 — 이론 글, 서적, 블로그, 강연, 커뮤니티 — 를 모은 큐레이션으로, 자동화 스크립트를 짤 줄 아는 사람이 테스터로서의 관점을 얻으려 할 때 쓰는 입구다.

## 페르소나
**테스트 코드는 쓰지만 "무엇을 테스트해야 하는가"를 배운 적이 없는 개발자, 혹은 QA를 처음 맡아 학습 경로를 짜야 하는 사람.** 도구는 익혔는데 케이스를 뽑을 때마다 감에 의존하고, 리뷰에서 "이 케이스는 왜 없냐"는 지적을 받으면 반박도 수긍도 못 한다. 탐색적 테스트, 오라클, 리스크 기반 같은 단어를 어디서부터 읽어야 할지 모른다.

## 이럴 때 연다
- 팀의 QA 온보딩 읽기 목록을 만들 때
- 테스트 이론·기법(탐색적 테스트, 리스크 기반, 오라클 등)의 대표 글을 찾을 때
- 테스트 관련 블로그·뉴스레터·커뮤니티를 구독 리스트에 추가할 때
- 자동화 도구 학습만 반복하다 정체된 느낌일 때 다음 단계 자료를 고를 때

## 이럴 땐 아니다
- 지금 당장 자동화 프레임워크를 골라야 하면 → `qa/awesome-test-automation.md`
- 체계적인 커리큘럼과 용어 정의가 필요하면 큐레이션보다 표준 실러버스가 낫다 → `qa/istqb-foundation-level.md`
- 테스트 전략을 백지에서 세우는 실제 작업 중이면 목록 대신 체크리스트형 모델을 → `qa/heuristic-test-strategy-model.md`
- 영상 강의 중심의 학습 경로를 원하면 → `qa/test-automation-university.md`

## 무엇이 들어있나
Awesome 시리즈 중에서도 "사람이 읽을 글" 비중이 높은 축이다. 도구 링크도 있지만 핵심은 테스트 이론과 커뮤니티 자료 쪽에 있고, 그래서 탐색적 테스트 진영(Bach, Bolton 계열)과 자동화 진영의 자료가 한 페이지에 섞여 있다.
이 혼재가 오히려 유용하다. 두 진영이 서로 다른 전제 위에 서 있다는 걸 알아채는 게 QA 학습의 초기 관문이기 때문이다.
큐레이션 특성상 항목별 깊이 차이가 크고, 링크가 죽은 것도 섞여 있다.

## 인용 포인트
- 신규 입사자용 학습 자료 목록의 출발점으로 그대로 옮겨 쓰기 좋다. 다만 내부용으로 옮길 때는 링크 생존 확인이 필요하다.
