# Satisfice — James Bach

https://www.satisfice.com/

## 한 줄
James Bach의 회사이자 개인 자료실 — Rapid Software Testing 방법론, 휴리스틱 모델, 블로그 글, 다운로드 가능한 도구·참고자료가 모여 있는 Context-Driven Testing 진영의 본진.

## 페르소나
**"테스트 케이스를 몇 건 작성했는가"로 QA를 평가받는 것에 근본적으로 회의를 느끼기 시작한 테스터 또는 테크리드.** 표준과 자격증이 말하는 프로세스대로 해도 중요한 버그는 항상 프로세스 밖에서 나온다. 이 불편함이 자기만의 착각인지, 아니면 이미 정리된 반대 입장이 있는지 확인하고 싶다. 그 반대 입장의 원 출처를 한 곳에서 훑고 싶은 사람.

## 이럴 때 연다
- RST 방법론, 휴리스틱 테스트 전략 모델 등 Bach의 원 자료를 출처째 인용해야 할 때
- 탐색적 테스트·리스크 분석·테스터 코칭 주제의 참고문헌을 모을 때(사이트에 주제별 정리가 있다)
- 표준 중심 테스트 프로세스에 대한 비판 논거를 원문에서 확인할 때
- 테스터 교육·코칭 프로그램을 설계하며 커리큘럼 참고 자료를 찾을 때

## 이럴 땐 아니다
- 방법론 자체를 바로 적용하고 싶은 것이면 사이트 루트가 아니라 `qa/rapid-software-testing.md` 로 바로 가라.
- 테스트 전략 수립용 체크리스트가 목적이면 `qa/heuristic-test-strategy-model.md`.
- 같은 진영이지만 "testing vs checking" 같은 개념 논의를 더 파고드는 글은 `qa/developsense-michael-bolton.md` 쪽에 많다.
- 실무자 커뮤니티의 폭넓은 사례가 필요하면 `qa/ministry-of-testing.md`.

## 무엇이 들어있나
"Software Testing for Serious People"을 표방하는 컨설팅·교육 회사 사이트다. 축은 셋이다 — (1) RST 방법론과 그 계열 교육 과정(RST Explored / Applied / Managed 등, 최근에는 AI를 다루는 과정도 있다), (2) 무료 공개 자료 — 블로그, 다운로드(도구·문서), 주제별 참고문헌 목록(탐색적 프로세스, 리스크 분석, 코칭 등), (3) 저서 안내 — *Lessons Learned in Software Testing*, *Secrets of a Buccaneer-Scholar*, *Taking Testing Seriously*.

성격상 중립적 레퍼런스가 아니라 **입장이 뚜렷한 저자의 자료실**이다. 테스팅은 표준화 가능한 공정이 아니라 맥락에 따라 달라지는 기량이라는 주장이 전체를 관통하며, ISO 29119 같은 표준화 시도에 대한 명시적 반대가 반복해서 등장한다. 그 편향을 알고 읽으면 균형추로서 매우 유용하다.

## 인용 포인트
- Context-Driven Testing 관련 주장을 인용할 때, 2차 블로그가 아니라 이 사이트의 원문을 출처로 다는 편이 논쟁에서 훨씬 강하다.
