# Example Mapping

https://cucumber.io/blog/bdd/example-mapping-introduction/

## 한 줄
스토리 하나를 규칙(파랑)·예시(초록)·질문(빨강) 카드로 25분 안에 펼쳐 놓고, "이 스토리 지금 개발 들어가도 되는가"를 카드 배치만 보고 판단하게 만드는 워크숍 기법 (Matt Wynne, 2015).

## 페르소나
**스프린트가 시작된 뒤에야 "이 경우엔 어떻게 되나요?"가 쏟아져 개발이 멈추는 팀의 개발자·QA.** 요구사항 문서는 있는데 경계 조건이 비어 있어, 구현 도중 기획자에게 물어보고 답을 기다리는 시간이 실제 코딩 시간보다 길다. 리파인먼트 회의는 한 시간씩 하는데도 끝나면 무엇이 합의됐는지 남는 게 없다. 필요한 건 BDD 도구가 아니라, 회의를 짧게 끝내면서 미결 질문을 눈에 보이게 만드는 진행 형식이다.

## 이럴 때 연다
- 리파인먼트/그루밍 회의가 길기만 하고 산출물이 남지 않을 때
- 스프린트 도중 "이 케이스는 어떻게 하죠" 질문으로 개발이 자주 멈출 때
- 스토리를 쪼개야 한다는 감은 있는데 어디서 잘라야 할지 근거가 없을 때
- QA를 개발 이후가 아니라 기획 단계로 끌어올 실용적 명분이 필요할 때
- 쿠폰 중복 적용, 부분 취소 환불 같이 규칙이 얽힌 요구사항을 경우별로 펼쳐야 할 때

## 이럴 땐 아니다
- 이렇게 뽑은 예시를 실행 가능한 명세로 옮기는 문법·도구가 필요하면 `qa/cucumber-bdd.md`
- 예시 기반 명세를 조직 차원의 프로세스로 정착시키는 이야기라면 `qa/specification-by-example.md`
- 무엇을 테스트할지 빠짐없이 훑는 전략 체크리스트가 필요하면 `qa/heuristic-test-strategy-model.md`

## 무엇이 들어있나
핵심은 산출물이 아니라 **신호**다. 카드가 테이블에 놓이는 모양 자체가 진단이 된다 — 빨간 카드(아무도 답 못 하는 질문)가 많으면 아직 개발에 들어갈 수 없다는 뜻이고, 파란 카드(규칙)가 많으면 스토리가 너무 크니 쪼개라는 뜻이며, 규칙 하나에 초록 카드(예시)가 지나치게 많이 붙으면 그 규칙 안에 서로 다른 요구가 엉켜 있다는 뜻이다.

25분이라는 타임박스도 도구다. 잘 이해되고 적절한 크기의 스토리라면 25분이면 끝나야 하고, 넘어간다는 것 자체가 크기나 불확실성의 문제를 알려주는 측정값이다. 끝에는 손가락 투표로 "개발 준비됨"을 결정한다.

Cucumber/Gherkin을 쓰지 않아도 성립한다는 점이 실무적으로 중요하다. 필요한 건 인덱스 카드와 세 사람(기획·개발·테스트)뿐이다.

## 인용 포인트
- "빨간 카드가 많으면 이 스토리는 아직 개발에 들어갈 수 없다" — 준비 안 된 스토리를 스프린트에 밀어 넣는 압박에 맞설 때, 개인의 판단이 아니라 회의 결과물로 반박할 수 있다.
- "25분 안에 안 끝나는 스토리는 너무 크거나 너무 불확실한 것" — 스토리 쪼개기의 기준을 감이 아니라 관측값으로 바꾸는 문장.

## 코드 예시

인덱스 카드 배치를 이슈에 붙일 수 있게 옮긴 형태 — 빨간 카드가 남아 있으면 `ready` 가 참이 될 수 없다는 판정 규칙까지 같은 파일에 적는다.

```yaml
# stories/SOLU-1421.example-map.yaml  (25분 타임박스, 3인 참석)
story: 부분 취소 시 쿠폰 할인 재계산
timebox_min: 25
elapsed_min: 31              # 초과 자체가 신호: 크기 또는 불확실성
rules:
  - rule: 정액 쿠폰은 남은 금액에 그대로 유지된다
    examples:
      - 30000원 주문 / 5000원 쿠폰 / 10000원 취소 → 할인 5000 유지
      - 30000원 주문 / 5000원 쿠폰 / 28000원 취소 → 할인 2000 로 축소
  - rule: 정률 쿠폰은 남은 금액 기준으로 다시 계산한다
    examples:
      - 30000원 주문 / 10% / 10000원 취소 → 할인 2000
questions:                   # 빨간 카드 — 답이 없으면 개발 불가
  - q: 쿠폰 최소 주문금액 미만으로 떨어지면 쿠폰을 회수하나
    owner: 기획
    blocking: true
ready: false                 # questions 중 blocking:true 가 있으면 false
```

`ready: false` 는 관측 결과일 뿐 강제력이 아니다 — 이 파일을 스프린트 진입 조건으로 참조하는 합의가 없으면, 빨간 카드를 적어 둔 채로 개발이 시작되는 건 똑같다.
