# Laws of UX

https://lawsofux.com/

## 한 줄
힉의 법칙, 피츠의 법칙, 야콥의 법칙 같은 인지심리학·인간공학 원칙을 UX 판단에 쓸 수 있게 한 장씩 짧게 정리하고, 각 항목마다 원 출처를 달아 둔 사이트.

## 페르소나
**디자인 리뷰에서 "이게 더 나아 보인다"는 취향 대립이 반복돼 중재할 언어가 없는 기획자·개발자.** 필터 옵션을 12개 노출할지 4개로 접을지, 결제 버튼을 얼마나 키울지 같은 결정이 매번 목소리 큰 사람 쪽으로 기운다. 근거를 대고 싶은데 "사용자 편의"라는 말 말고는 쓸 단어가 없고, 논문을 뒤질 시간은 없다.

## 이럴 때 연다
- 리뷰나 기획 문서에서 UI 결정에 이름 붙은 근거를 달아야 할 때
- 옵션 개수, 버튼 크기·위치, 폼 단계 수를 두고 팀 의견이 갈릴 때
- "우리 서비스만의 새로운 인터랙션"을 제안받았는데 기존 관습을 깨는 비용을 설명해야 할 때 (야콥의 법칙)
- 신입 팀원에게 UX 판단의 공통 어휘를 빠르게 심어 줄 때

## 이럴 땐 아니다
- 실제 화면을 놓고 결함을 훑는 점검표가 필요하면 `design/nn-g-10-usability-heuristics.md`
- 특정 컴포넌트(폼, 메뉴, 버튼)의 구체적 설계 지침은 `design/nn-g-design-patterns.md`
- 원칙이 아니라 실제 제품의 개선 전후 사례가 필요하면 `design/growth-design.md`

## 무엇이 들어있나
각 법칙은 한 문장 정의 + 짧은 해설 + 출처(원 논문이나 저서) 링크로 구성되어 카드처럼 훑을 수 있다. 힉의 법칙(선택지가 늘면 결정 시간이 늘어난다), 피츠의 법칙(목표까지의 거리와 크기가 조작 시간을 결정한다), 야콥의 법칙(사용자는 다른 사이트에서 보낸 시간이 훨씬 길기 때문에 우리 사이트도 그들과 같이 동작하기를 기대한다), 밀러의 법칙, 포스텔의 법칙, 미학적-사용성 효과, 도허티 임계값 등이 실린다. 주의할 점도 사이트 자체가 짚는다 — 이 "법칙"들은 물리 법칙이 아니라 경험칙이고, 힉의 법칙을 근거로 옵션을 무조건 줄이는 식의 오용이 흔하다.

## 인용 포인트
- 야콥의 법칙은 "업계 관습을 따르자"는 주장에 이름을 붙여 준다 — 장바구니 아이콘 위치, 결제 단계 순서 논쟁에서 특히 유용하다.
- 도허티 임계값(약 400ms)은 응답 속도 개선의 UX 근거로 성능 작업 티켓에 붙일 수 있다.
