# Figma Resource Library

https://www.figma.com/resource-library/

## 한 줄
디자인 프로세스·협업·디자인 시스템 용어를 개념 단위로 설명한 Figma의 입문 아티클 모음 — 디자이너가 아닌 사람이 디자인 논의의 어휘를 맞추기 위해 쓰는 사전에 가깝다.

## 페르소나
**디자이너와 회의를 하는데 오가는 단어의 정확한 뜻을 몰라서 되묻지도 못하는 기획자·개발자.** 와이어프레임과 목업과 프로토타입의 차이, 디자인 스프린트가 뭘 산출하는지, 사용성 테스트를 몇 명으로 하는지 같은 것을 물어보기엔 늦었고, 검색하면 광고성 글만 나온다. 협업 절차를 팀에 제안해야 하는데 용어부터 흔들린다.

## 이럴 때 연다
- 디자인 프로세스 용어(와이어프레임/목업/프로토타입, 디자인 스프린트, 디자인 씽킹)를 정리할 때
- 디자인-기획-개발 협업 절차를 문서로 제안하기 전에 표준적인 어휘를 맞출 때
- 디자인 시스템·UX 리서치 같은 주제를 팀에 처음 설명해야 할 때
- 신규 입사자에게 읽힐 입문 링크가 필요할 때

## 이럴 땐 아니다
- 실행 가능한 시스템 운영·거버넌스 논의는 `design/design-systems.md`
- 사용성 평가를 실제로 설계·수행하려면 `design/nn-g-discount-usability.md`와 `design/nn-g-10-usability-heuristics.md`
- 발견(discovery) 단계 방법론은 `planning/double-diamond.md`, `planning/design-sprint.md`
- 화면 품질 자체를 올리는 실전 기법은 `design/refactoring-ui.md`

## 무엇이 들어있나
디자인 기초, 디자인 프로세스, 협업, 디자인 시스템, 프로토타이핑, UX 리서치 등의 주제로 나뉜 설명 아티클 모음이다. 각 글은 용어를 정의하고 대략의 절차와 산출물을 소개하는 입문 수준으로, 깊이보다 진입 문턱을 낮추는 데 초점이 있다.
Figma가 만든 마케팅 성격의 콘텐츠라는 점은 감안해야 한다 — 방법론의 논쟁적 지점이나 한계는 거의 다루지 않고, Figma 워크플로를 전제로 서술되는 경우가 많다. 그래서 **의사결정의 근거로 인용하기에는 약하고, 어휘를 맞추는 용도로는 충분하다.**
깊이가 필요해지는 순간(리서치 설계, 시스템 거버넌스, 접근성 판정)에는 각각의 정본 자료로 넘어가야 한다.

## 인용 포인트
- 비디자이너에게 디자인 절차를 설명할 때 공통 어휘를 세우는 출발점으로 쓴다. 다만 팀 규칙의 근거 문서로는 삼지 않는 편이 낫다.
