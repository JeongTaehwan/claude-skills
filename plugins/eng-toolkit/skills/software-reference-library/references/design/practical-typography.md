# Practical Typography

https://practicaltypography.com/

## 한 줄
변호사이자 폰트 디자이너인 Matthew Butterick이 쓴 웹 타이포그래피 교본 — 취향이 아니라 "독자의 시간을 아끼는가"를 기준으로 문장부호·자간·행간·본문 폭까지 판정한다.

## 페르소나
**디자이너 없이 사내 문서·릴리스 노트·랜딩 페이지를 직접 만들어야 하는 개발자.** 폰트 크기와 줄 간격을 감으로 넣었더니 "왠지 아마추어 같다"는 피드백이 오는데, 무엇이 문제인지 지목이 안 된다. 디자인 이론서를 읽을 시간은 없고, 지금 이 문서를 읽을 만하게 만드는 몇 개의 규칙이 필요하다.

## 이럴 때 연다
- 문서·블로그·랜딩 페이지의 본문 조판(글자 크기, 행간, 한 줄 길이, 여백)을 정할 때
- 디자인 시스템의 타이포 스케일 근거를 세울 때
- 굽은 따옴표, 대시(하이픈/엔대시/엠대시), 말줄임표 같은 문장부호 사용 규칙을 팀 문서에 정할 때
- 시스템 기본 폰트 대신 무엇을 쓸지 고를 때 (폰트 추천 절이 따로 있다)
- 이력서·계약서 같은 인쇄 지향 문서를 만들어야 할 때 (샘플 문서 절)

## 이럴 땐 아니다
- 웹 레이아웃(그리드, 반응형 컴포지션) 문제라면 `design/every-layout.md`
- 시각 위계·간격·색 전반을 개발자 관점으로 배우려면 `design/refactoring-ui.md`
- CSS 구현 기법(가변 폰트, `clamp()`, 폰트 로딩)은 `design/css-tricks-guides.md`
- 본문 대비비·가독성의 접근성 판정 기준은 `design/wcag-2-2.md`

## 무엇이 들어있나
구성은 조판(문장부호·간격·특수문자), 텍스트 서식(폰트·크기·강조), 폰트 추천, 페이지 레이아웃(여백·정렬), 샘플 문서, 부록 순이다. 앞머리의 "Typography in ten minutes"는 전체를 몇 개 규칙으로 압축한다 — 본문 글자 크기와 행간, 한 줄에 들어가는 글자 수, 여백 확보가 폰트 선택보다 훨씬 큰 차이를 만든다는 것. 통념을 정면으로 반박하는 대목이 많다: 문장 사이 두 칸은 타자기 습관이지 조판 규칙이 아니고, 직선 따옴표(`"`)는 따옴표가 아니며, 밑줄과 전각 강조는 대체로 나쁜 선택이다. 저자는 규칙의 근거를 수백 년 인쇄 전통에서 끌어오되, 결론은 늘 실무적으로 내린다. 사이트 전체가 무료로 공개되어 있고 광고 없이 독자 후원으로 운영된다.

## 인용 포인트
- "폰트를 바꾸기 전에 크기·행간·줄 길이·여백부터 고쳐라"는 우선순위는, 디자인 개선 요청이 폰트 교체 논쟁으로 흐를 때 방향을 되돌리는 데 쓸 수 있다.
