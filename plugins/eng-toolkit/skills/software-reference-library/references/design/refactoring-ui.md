# Refactoring UI

https://www.refactoringui.com/

## 한 줄
Tailwind CSS를 만든 Adam Wathan과 디자이너 Steve Schoger가 "재능 말고 전술로 디자인하라(Design with tactics, not talent)"를 표어로 삼아, 개발자가 그대로 적용할 수 있는 시각 디자인 규칙을 개선 전후 화면과 함께 묶은 유료 책·자료 패키지.

## 페르소나
**기능은 다 되는데 화면이 "만든 티가 나서" 매번 디자이너 손을 빌려야 하는 개발자.** 어디가 이상한지 지목은 못 하고, 색을 바꿔 보고 여백을 늘려 봐도 나아지지 않는다. 디자인 이론이 아니라 "이럴 땐 이렇게 해라" 수준의 구체적 조작 목록이 필요하고, 사내 관리자 화면이나 사이드 프로젝트를 혼자 마감까지 끌고 가야 한다.

## 이럴 때 연다
- 디자이너 없이 관리자 화면·대시보드·랜딩 페이지를 혼자 만들어야 할 때
- 시안이 "밋밋하다"는 피드백을 받았는데 무엇을 조정할지 모를 때
- 색 팔레트와 간격 스케일을 감이 아니라 규칙으로 정하고 싶을 때
- 빈 상태(empty state), 카드, 표 같은 반복 요소의 완성도를 올릴 때
- 팀에 시각 위계에 관한 공용 어휘를 심을 때

## 이럴 땐 아니다
- 글자·문장부호 조판 자체가 문제라면 `design/practical-typography.md`
- 레이아웃을 CSS 원리로 다루고 싶으면 `design/every-layout.md`
- 조직 차원의 디자인 시스템 구축·운영은 `design/design-systems.md`, `design/material-design-3-foundations.md`
- 사용성·인터랙션 결함 점검은 `design/nn-g-10-usability-heuristics.md`
- 접근성 기준은 여기서 다루지 않는다 — `design/wcag-2-2.md`

## 무엇이 들어있나
218쪽 PDF 책(약 50개 시각 챕터)과 영상 튜토리얼 3편, 200개 이상의 UI 컴포넌트 예시 갤러리, 색 팔레트 12종 이상, 폰트 추천 30종 이상, 아이콘 200종으로 구성된 유료 패키지다. 책은 위계, 여백, 타이포그래피, 색, 깊이(그림자), 이미지 사용 등 아홉 개 큰 절로 나뉜다. 관통하는 주장은 두 가지다 — 첫째, 디자인 실력은 감각이 아니라 적용 가능한 전술의 목록이다. 둘째, 초보가 흔히 손대는 것(폰트 고르기, 색 고르기)보다 위계와 여백 조정이 결과를 훨씬 많이 바꾼다. 색을 회색조 단계로 먼저 설계하고 나중에 색을 얹으라거나, 글자 굵기·크기 대신 색 명도로 위계를 만들라는 식의 구체적 지침이 개선 전후 이미지와 함께 제시된다. 저자 스스로 "예전엔 디자인을 못했다"는 입장에서 쓴 책이라 설명이 개발자 어휘로 되어 있다.

## 인용 포인트
- "Design with tactics, not talent"는 디자인을 배울 수 있는 기술로 규정할 때 쓰기 좋은 한 문장이다.
- "폰트나 색을 바꾸기 전에 위계와 여백부터"라는 우선순위는 UI 개선 티켓의 작업 순서를 정할 때 그대로 쓸 수 있다.

## 코드 예시

책의 전술 네 개 — 회색조 먼저, 간격은 스케일에서만 고르기, 위계는 크기가 아니라 색 명도로, 그림자는 고도 — 를 카드 하나에 적용한 형태.

```css
:root {
  /* 1. 색은 회색조 단계부터 만든다. 색상은 나중에 얹는다 */
  --gray-900: #1a202c;
  --gray-700: #4a5568;
  --gray-500: #a0aec0;
  --gray-200: #e2e8f0;

  /* 2. 간격은 연속값이 아니라 비선형 스케일에서만 고른다 */
  --space-2: 0.5rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
}

/* 3. 위계는 글자 크기를 키우는 대신 색 명도로 만든다 */
.card__title { color: var(--gray-900); font-weight: 600; }
.card__body  { color: var(--gray-700); }
.card__meta  { color: var(--gray-500); font-size: 0.875rem; }

/* 4. 그림자는 장식이 아니라 '얼마나 떠 있는지'의 스케일이다 */
.card {
  padding: var(--space-6);
  border: 1px solid var(--gray-200);
  border-radius: 0.5rem;
  box-shadow: 0 1px 3px rgb(0 0 0 / 0.1), 0 1px 2px rgb(0 0 0 / 0.06);
}
```

`--gray-500`은 흰 배경에서 대비가 약 2.1:1이라 본문에 쓰면 WCAG AA에 한참 못 미친다 — 명도로 위계를 만드는 전술은 "보조 정보에만"이라는 전제가 붙어야 성립한다. 팔레트가 라이트 모드 한 방향만 정의돼 있다는 것도 이 코드에는 안 보인다.
