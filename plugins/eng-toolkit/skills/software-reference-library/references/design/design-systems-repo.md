# Design Systems Repo

https://designsystemsrepo.com/

## 한 줄
공개된 디자인 시스템 사례와 관련 아티클·도구·강연을 모아둔 큐레이션 인덱스 — 특정 시스템을 배우는 곳이 아니라, "다른 회사들은 이 문제를 어떻게 문서화했나"를 한 번에 훑는 출발점이다.

## 페르소나
**사내 디자인 시스템 문서 사이트를 처음 만들면서, 무엇을 어디까지 써야 하는지 감이 없는 사람.** 컴포넌트마다 어떤 항목을 적어야 하는지(용도, 변형, 접근성, 코드, 하지 말 것), 문서 사이트의 정보 구조를 어떻게 짜야 하는지 정답이 없어서 첫 페이지에서 멈춰 있다. 사례를 대량으로 비교해야 하는데 하나씩 검색하기엔 비효율적이다.

## 이럴 때 연다
- 사내 시스템 문서의 구조·범위를 정하기 전에 여러 회사 사례를 몰아서 볼 때
- 우리와 비슷한 도메인(커머스, 엔터프라이즈, 핀테크)의 공개 시스템을 찾을 때
- 디자인 시스템 관련 도구(토큰 파이프라인, 문서화 도구, Figma 플러그인)를 조사할 때
- 관련 강연·책을 한 번에 훑어보고 학습 경로를 짤 때

## 이럴 땐 아니다
- 컴포넌트 이름·props·변형을 시스템 간 나란히 비교하려면 `design/the-component-gallery.md` 가 더 직접적이다
- 시스템 운영·거버넌스의 방법론 글이 필요하면 `design/design-systems.md`
- 실제로 채택해 쓸 시스템의 스펙이 필요하면 `design/carbon-design-system.md`, `design/polaris.md`, `design/primer.md`, `design/spectrum.md`
- 개별 컴포넌트 구현의 접근성 요건은 `design/aria-authoring-practices-guide.md`

## 무엇이 들어있나
"A frequently updated collection of Design System examples, articles, tools and talks"라는 자기 소개대로, 다섯 종류의 큐레이션 목록이다 — 실제 회사들의 디자인 시스템 갤러리, 아티클, 도구·플러그인, 추천 도서, 강연 영상. 제출 폼을 통해 커뮤니티 기여를 받는다.
Jad Limcaco가 운영하는 개인 큐레이션 사이트이며, 표준이나 규범을 제시하지 않는다. 가치는 판단이 아니라 **범위**에 있다 — 특정 결정을 앞두고 사례를 폭넓게 확보해야 할 때 유용하고, 어떤 결정을 내려야 하는지 자체가 궁금할 때는 다른 자료가 낫다.
갤러리 항목은 각 회사의 공개 문서 사이트로 바로 연결되므로, 문서 구조를 비교하며 우리 문서의 목차를 역설계하기 좋다.

## 인용 포인트
- "우리 문서에 이 항목까지 써야 하나"라는 논의에, 동종 업계 공개 시스템 여러 개의 문서 구조를 근거로 제시할 수 있다.
