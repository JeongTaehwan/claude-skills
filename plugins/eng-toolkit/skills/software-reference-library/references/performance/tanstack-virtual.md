# TanStack Virtual — 헤드리스 리스트 가상화

https://github.com/TanStack/virtual

## 한 줄
마크업과 스타일을 완전히 내 손에 두면서 보이는 행만 렌더링하는 헤드리스 가상화 라이브러리. React 18+, 동적 행 높이를 지원하고 react-query와 같은 생태계(TanStack)다.

## 페르소나
**상품 목록·주문 내역 수천 건을 그대로 렌더링해서, 느린 기기에서 스크롤이 뚝뚝 끊기고 첫 렌더가 한참 걸리는 화면을 맡은 엔지니어.** 가상화가 답인 건 알겠는데, 기성 리스트 컴포넌트의 DOM 구조·스타일 제약에 디자인을 맞추고 싶지는 않다.

## 이럴 때 연다
- 상품 목록·주문 내역 같은 긴 리스트의 가상화 1순위로(소스 판단) — react-query를 쓰는 프로젝트면 특히
- 디자인 시스템의 마크업·스타일을 유지한 채 가상화 로직만 얹고 싶을 때 — 헤드리스의 존재 이유
- 행 높이가 내용에 따라 달라지는(동적 높이) 리스트를 가상화할 때
- react-query 무한 스크롤과 가상화를 조합할 때 — 같은 TanStack 생태계라 결이 맞는다

## 이럴 땐 아니다
- 헤드리스가 부담스럽고 컴포넌트를 조립하는 방식이 편하다면, 또는 그리드 가상화가 필요하다면 `performance/react-window.md`
- 목록이 느린 원인이 렌더링이 아니라 데이터 전송이면 가상화는 답이 아니다 — 페이지네이션·응답 다이어트가 먼저다
- 목록의 로딩 중 표시가 문제라면 `performance/react-loading-skeleton.md`

## 무엇이 들어있나
스크롤 컨테이너에서 어떤 인덱스가 보이는지, 각 행을 어디에 배치할지를 계산해 주는 훅/코어 — DOM은 한 조각도 강제하지 않는다. 보이는 행만 렌더링하므로 수만 행에서도 DOM 크기가 일정하게 유지된다. 동적 행 높이 측정, 수평·수직·그리드 배치를 지원하고 React 외 프레임워크 어댑터도 있다.

## 인용 포인트
- 긴 목록 성능 문제의 표준 해법이 "가상화"이고, 그 현행 1순위 구현이라는 기술 선정 근거(특히 react-query 프로젝트).
- 헤드리스 접근이 디자인 시스템과 가상화 로직의 결합을 끊는다는 아키텍처 논거.
