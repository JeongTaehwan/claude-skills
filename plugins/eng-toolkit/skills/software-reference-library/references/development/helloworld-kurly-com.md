# 컬리 기술블로그 (Hello World)

https://helloworld.kurly.com/

## 한 줄
주문·입고·물류처럼 재고와 배송이 물리 세계와 물려 있는 이커머스 도메인의 실무 글이 꾸준히 올라오는 한국어 기술블로그.

## 페르소나
**외부 시스템(공급사·물류사)에서 들어오는 데이터를 우리 재고·주문 상태와 맞추다가 정합성이 깨지는 문제를 겪는 커머스 백엔드 엔지니어.** 이론서에는 "멱등성을 보장하라" 정도만 있고, 실제로 지연 도착·중복 전송·부분 실패가 섞였을 때 어떤 구조로 막았는지의 사례가 없다. 같은 도메인에서 같은 문제를 이미 겪은 팀의 기록이 필요하다.

## 이럴 때 연다
- 입고·재고 동기화처럼 외부 인입 데이터를 안전하게 반영하는 구조를 설계할 때
- 주문·배송 상태 전이 모델을 잡으면서 국내 커머스 사례를 참고할 때
- 이커머스 맥락의 QA·테스트 자동화 사례가 필요할 때
- 데이터/ML 을 물류·배송 운영에 붙인 사례(예: 배송 사진 기반 판정 같은 온디바이스 적용)를 볼 때
- 프론트엔드 빌드 도구·모노레포 마이그레이션 같은 실무 전환기를 참고할 때
- 사내에 AI 도구를 도입하려는데 실제 운용기가 필요할 때 — 최근 이 블로그는 AI 에이전트 운용·LLM 도메인 지식 주입 사례를 비중 있게 다룬다

## 이럴 땐 아니다
- 도메인 사례가 아니라 분산 시스템의 원리·트레이드오프가 필요하면 `architecture/designing-data-intensive-applications.md`, `architecture/amazon-builders-library.md`
- 다른 국내 기업의 관점이 필요하면 `development/techblog-woowahan-com.md`(배달·주문), `development/toss-tech.md`(금융), `development/tech-kakaopay-com.md`(결제), `development/tech-socarcorp-kr.md`(모빌리티)
- 한국어 학습 자료 큐레이션이 목적이면 `development/goquality-dev-contents.md`
- 이벤트 기반 아키텍처의 일반론은 `architecture/enterprise-integration-patterns.md`

## 무엇이 들어있나
글이 기술 / AI·데이터 / 프로덕트 세 갈래로 분류돼 있어, 인프라 글과 도메인 글, 조직·프로세스 글을 구분해서 훑을 수 있다.
가장 차별적인 지점은 도메인이다. 신선식품 커머스라 재고·입고·배송이 시간과 물리 제약을 강하게 받고, 그래서 "정합성이 깨지면 실제 물건이 틀어진다"는 전제에서 쓴 글이 나온다. 일반적인 웹 서비스 블로그에서 잘 안 나오는 문제 설정이다.
최근에는 AI 도구를 실제 개발 조직 운영에 붙인 기록(에이전트 병렬 운용, 팀 리드 업무 재설계, 대량 대화에서 얻은 관찰)이 눈에 띄게 늘었다. 도구 소개가 아니라 운용기 성격이라 사내 도입 논의의 참고 사례로 쓸 만하다.
회사 블로그이므로 실패보다 성공 서사 쪽에 기울 수 있다는 점은 감안하고 읽는 게 좋다.

## 인용 포인트
- 국내 커머스 도메인의 구체적 사례를 근거로 들 수 있어, 해외 사례로는 잘 설득되지 않는 논의(예: 물류 연동 구조)에서 유용하다.
