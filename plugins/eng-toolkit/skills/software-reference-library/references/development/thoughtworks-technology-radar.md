# ThoughtWorks Technology Radar

https://www.thoughtworks.com/radar

## 한 줄
ThoughtWorks 가 실제 고객 프로젝트에서 쓴 기술만 골라 Adopt / Trial / Assess / Hold 네 단계로 분류해 반기마다 내는 리포트 — 특히 "Hold" 항목이 유행하는 기술에 제동을 걸 때의 인용원이 된다.

## 페르소나
**팀에서 "이거 도입하자"는 제안이 올라왔는데, 유행인지 성숙한지 판단할 근거가 없어 결정을 미루고 있는 테크리드.** 벤더 문서와 블로그 글은 전부 장점만 말하고, 반대할 근거는 개인 직감밖에 없다. 도입 여부를 취향 싸움이 아니라 외부 기준으로 정리하고 싶다.

## 이럴 때 연다
- 새 프레임워크·DB·플랫폼 도입 제안이 왔고 "지금이 이른가"를 판단해야 할 때
- 이미 쓰고 있는 기술이 업계에서 어떤 상태(성숙/사양)로 보이는지 확인할 때
- 기술 선택 ADR 에 "우리만의 판단"이 아니라는 외부 근거를 붙일 때
- 반기별 기술 스택 점검에서 정리 대상(Hold 로 강등된 것)을 찾을 때
- 반대로, 이미 Adopt 인 기술을 도입 못 하고 있는 이유를 조직에 설명할 때

## 이럴 땐 아니다
- 기술의 진화 단계를 조직·시장 맥락에서 지도로 그려야 한다면 `planning/wardley-mapping.md` 쪽이 도구다
- 클라우드 네이티브 생태계에서 어떤 도구가 어떤 범주에 있는지 전수 목록은 `architecture/cncf-landscape.md`
- 실제 웹에서 무엇이 얼마나 쓰이는지 실측 데이터가 필요하면 `development/web-almanac.md`
- 개인 학습 경로 설계는 `development/developer-roadmap.md`

## 무엇이 들어있나
Radar 는 "우리가 직접 써 본 것만 싣는다"는 원칙으로 만들어진다. 그래서 시장 점유율이나 인기와 무관하게, 컨설팅 현장에서 겪은 경험이 등급의 근거다 — 시장조사 리포트와 성격이 다르다.
분류가 네 링으로 되어 있고 의미가 명확하다. Adopt 는 기본값으로 쓰라는 뜻, Trial 은 감당 가능한 프로젝트에서 써 보라는 뜻, Assess 는 추적하되 도입은 아직, Hold 는 새로 시작하지 말라는 뜻이다. Hold 는 "나쁘다"가 아니라 "새 프로젝트에서 기본 선택지로 삼지 말라"는 뉘앙스로, 이 구분이 논쟁에서 자주 오해된다.
항목은 Techniques / Tools / Platforms / Languages & Frameworks 네 사분면으로 나뉜다. 특히 Techniques 사분면이 도구가 아닌 실천법(예: 배포·테스트·데이터 관행)을 다뤄서, 도구 선택보다 오래 유효한 편이다.
과거 판본이 모두 남아 있어 특정 기술의 등급 변화를 시계열로 볼 수 있다. 어떤 기술이 Assess → Trial → Adopt 로 몇 년에 걸쳐 올라갔는지, 혹은 Hold 로 떨어졌는지를 근거로 삼을 수 있다.

## 인용 포인트
- "Hold 에 올라와 있다"는 도입 반대 의견에 붙일 수 있는 가장 짧은 외부 근거다.
- 네 링의 정의 자체가 팀 내 기술 도입 프로세스 등급 체계로 그대로 차용할 만하다 — 사내 레이더를 만드는 조직이 실제로 많다.
- 특정 기술의 등급 변화 이력은 "이건 유행이 아니라 몇 년째 자리 잡은 것"을 보여줄 때 쓸 수 있다.
