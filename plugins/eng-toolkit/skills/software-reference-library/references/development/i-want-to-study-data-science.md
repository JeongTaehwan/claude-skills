# I-want-to-study-Data-Science

https://github.com/Team-Neighborhood/I-want-to-study-Data-Science

## 한 줄
데이터 직군으로 가려는 사람이 "무엇부터, 어떤 순서로"를 묻게 되는 지점마다 한국어 자료를 붙여 둔 위키형 학습 로드맵 — 코드 저장소가 아니라 경로 안내다.

## 페르소나
**백엔드에서 일하다 추천·이상탐지 같은 데이터 업무를 맡게 됐는데, 어디까지가 본인이 배워야 할 범위인지조차 모르는 엔지니어.** 데이터 분석가·데이터 엔지니어·ML 엔지니어가 뭐가 다른지부터 흐릿하고, 강의를 검색하면 난이도와 전제가 제각각이라 순서를 못 잡는다. 커리큘럼보다 먼저 지도가 필요하다.

## 이럴 때 연다
- 데이터 직군의 역할 구분(분석가 / 엔지니어 / ML 엔지니어 / 사이언티스트)을 정리해야 할 때
- 필요한 기초(선형대수, 파이썬, 리눅스, Git)의 학습 순서를 잡을 때
- 특정 하위 분야(컴퓨터 비전, NLP, 추천 시스템, 시계열, 강화학습)에 처음 진입하며 한국어 입문 자료를 찾을 때
- 논문 읽는 법·구현하는 법처럼 방법 자체가 막힐 때
- 포트폴리오(캐글, 대회, 블로그)와 취업 준비 경로를 설계할 때
- 팀원의 학습 계획을 함께 짜 줘야 하는데 본인 전문 분야가 아닐 때

## 이럴 땐 아니다
- 일반 소프트웨어 개발 학습 경로라면 `development/developer-roadmap.md`(영문, 시각적 로드맵)
- 한국어 개발 콘텐츠 전반의 큐레이션은 `development/goquality-dev-contents.md`
- 면접 질문 정리는 `development/interview-question-for-beginner.md`
- 데이터 파이프라인·저장소 설계 같은 시스템 쪽 문제는 학습 로드맵이 아니라 `architecture/designing-data-intensive-applications.md`
- 실험 설계·지표 해석은 데이터 분석 학습이 아니라 `planning/trustworthy-online-controlled-experiments.md`

## 무엇이 들어있나
본문 대부분이 저장소 위키에 있고, README 는 진입점 역할을 한다. 항목은 "무엇을 공부하나"보다 "이 질문을 받았을 때 어디를 보나"에 가깝게 배치돼 있다.
직군 구분 → 기초 스킬 → 세부 분야 → 실무·커리어 순으로 층이 나뉘어, 어느 단계에 있든 자기 위치를 찾고 다음 한 칸을 고를 수 있다.
FAQ, 커뮤니티·스터디 그룹 정보, 후기 모음처럼 학습 자료 바깥의 정보도 포함돼 있어 방향 설정에 쓸모가 있다.
크라우드소싱 기반이라 항목 간 깊이 편차가 있고 오래된 링크가 섞일 수 있다. 도구·프레임워크 의존 내용은 갱신 여부를 확인하고 쓰는 게 안전하다.
라이선스가 CC BY-ND 이므로 내용을 잘라 수정 배포하는 용도로는 맞지 않는다 — 링크로 참조하는 쪽이 안전하다.
