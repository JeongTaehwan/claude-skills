# goQuality-dev-contents

https://github.com/Integerous/goQuality-dev-contents

## 한 줄
국내 개발자들이 실제로 추천한 한국어 개발 콘텐츠를 주제별로 모은 큐레이션 저장소 — 번역서·강의 링크 나열이 아니라 블로그 글·발표 영상 단위로 골라 둔 목록이다.

## 페르소나
**후배나 신규 입사자에게 "이거 읽어봐"를 던져야 하는데, 영어 원문 자료만 알고 있어서 실제로 안 읽히는 경험을 반복한 시니어.** 좋은 자료는 대개 영문이고, 한국어로 된 것은 검색해도 품질 편차가 커서 골라내는 데 시간이 든다. 이미 걸러진 한국어 목록이 있으면 온보딩 문서의 절반이 해결된다.

## 이럴 때 연다
- 신규 입사자 온보딩 읽을거리를 한국어로 구성할 때
- 특정 주제(예: JPA, 스프링, 인프라, 커리어)의 한국어 입문 자료를 빠르게 찾을 때
- 스터디 커리큘럼을 짜면서 주차별 읽을 글을 고를 때
- 영문 자료를 추천했다가 반응이 없었던 주제에 대해 한국어 대체재를 찾을 때

## 이럴 땐 아니다
- 특정 회사의 실무 사례 글을 원한다면 기술블로그를 직접 보는 게 빠르다 — `development/techblog-woowahan-com.md`, `development/toss-tech.md`, `development/tech-kakao-com.md`, `development/line-engineering.md`, `development/naver-d2.md`
- 면접 준비용 질문 정리는 `development/interview-question-for-beginner.md`
- 데이터 사이언스 쪽 한국어 학습 경로는 `development/i-want-to-study-data-science.md`
- 학습 순서를 시각적 로드맵으로 보고 싶으면 `development/developer-roadmap.md`(영문)
- 영문 큐레이션의 폭이 필요하면 `development/professional-programming.md`, `development/every-programmer-should-know.md`

## 무엇이 들어있나
주제별 분류 아래에 개별 글·영상 링크가 짧은 설명과 함께 달려 있다. 항목 단위가 "책"이나 "사이트"가 아니라 글 하나여서, 스터디 한 회차 분량으로 바로 잘라 쓸 수 있다는 게 실제 쓸모다.
커뮤니티 추천 기반이라 항목 품질이 균일하지는 않고, 오래된 링크가 섞여 있을 수 있다. 최신성이 중요한 주제(프레임워크 버전 의존 내용)는 발행 시점을 확인하고 쓰는 게 안전하다.
개발 기술뿐 아니라 커리어·성장·조직 관련 글도 함께 분류돼 있어서, 기술 외 온보딩 자료로도 쓰인다.

## 인용 포인트
- 한국어 자료를 추천할 때 개인 취향 목록 대신 "커뮤니티에서 반복 추천된 목록"이라는 근거를 붙일 수 있다.
