# Engineering Manager 자료 모음

https://github.com/ryanburgess/engineer-manager

## 한 줄
엔지니어링 매니저 역할에 관한 아티클·책·팟캐스트·뉴스레터를 주제별로 모아 둔 큐레이션 저장소 — 스스로 글을 쓰지 않고 남의 글을 잘 분류해 놓는 종류의 자료다.

## 페르소나
**개발은 잘하는데 어제 처음 매니저가 된 사람.** 1:1 을 뭘 물어봐야 하는지, 성과 피드백을 어떻게 주는지, 팀원의 커리어 성장을 어떻게 다루는지에 대한 훈련을 받은 적이 없다. 당장 다음 주 1:1 이 잡혀 있는데 검색하면 나오는 글의 품질 편차가 너무 커서 무엇부터 읽어야 할지 모른다.

## 이럴 때 연다
- 처음 매니저 역할을 맡아 읽을거리의 출발점이 필요할 때
- 1:1, 성과 리뷰, 채용, 온보딩 같은 특정 주제에 대해 이미 검증된 글 몇 개를 빠르게 찾고 싶을 때
- 팀 내 성장 프레임워크(레벨 정의, 커리어 래더)를 만들면서 다른 회사 사례를 훑을 때
- 매니저 트랙 vs IC 트랙 결정을 앞두고 두 경로의 실제 일이 무엇인지 읽어 볼 때

## 이럴 땐 아니다
- 링크 모음이 아니라 하나의 일관된 체계가 필요하다면 `development/awesome-cto.md` 나 실제 운영 매뉴얼인 `planning/gitlab-handbook.md` 가 낫다
- 엔지니어링 조직의 성과를 지표로 말해야 하는 문제는 `development/dora.md`
- 코드 리뷰 문화·기술적 의사결정 프로세스 같은 실무 규약은 `development/google-engineering-practices.md`, `development/software-engineering-at-google.md`
- 개인 기술 학습 로드맵은 `development/developer-roadmap.md`

## 무엇이 들어있나
매니저 역할 전반 — 1:1, 피드백, 채용과 면접, 팀 빌딩, 성장·커리어, 문화, 원격 근무 등 — 을 주제 카테고리로 나눠 링크를 배치한다. 각 링크에 긴 해설은 없고 제목과 출처 위주라, 읽을 것을 고르는 단계에서 쓰는 도구지 읽는 대상 자체는 아니다.
큐레이션 저장소의 일반적 한계가 그대로 있다. 커뮤니티 기여로 항목이 늘어나므로 항목마다 품질과 최신성이 고르지 않고, 링크가 죽어 있을 수 있다. 하나의 관점으로 정렬된 교재를 기대하면 실망한다.
반대로 강점은 폭이다. 특정 상황(퇴사 면담, 저성과자 대응, 팀 분할)에 대해 최소 한두 개의 출발점 글은 거의 항상 있다.
