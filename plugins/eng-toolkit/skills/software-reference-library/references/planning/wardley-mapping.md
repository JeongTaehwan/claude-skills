# Wardley Mapping (Learn Wardley Mapping)

https://learnwardleymapping.com/

## 한 줄
사용자 니즈에서 내려오는 가치사슬(세로축)과 각 구성요소의 진화 단계(가로축: 제네시스 → 맞춤 제작 → 상품 → 유틸리티)로 전략 지형을 그리는 기법을, Simon Wardley의 원저를 바탕으로 학습용으로 재구성한 사이트.

## 페르소나
**"이건 직접 만들어야 한다"와 "그냥 사서 쓰자"가 매번 취향 싸움으로 끝나는 조직의 아키텍트/기술 리드.** 결제 모듈, 검색, 추천, 인증 — 어디에 사람을 넣고 어디를 외부에 맡길지 판단할 공통 기준이 없어서, 결정이 그때그때 담당자의 선호로 정해진다. 3년 뒤 그 선택들이 왜 그랬는지 설명도 안 된다.

## 이럴 때 연다
- 자체 개발 vs 구매/SaaS 결정을 반복하는데 판단 축이 없을 때
- 어디에 엔지니어를 투자하고 어디를 상품화된 것으로 대체할지 로드맵을 그릴 때
- 경쟁 환경이나 기술 지형이 어떻게 움직일지를 팀에 그림으로 설명해야 할 때
- 아키텍처 결정의 배경(전략적 위치)을 문서에 남기고 싶을 때

## 이럴 땐 아니다
- Simon Wardley 본인의 원문 연재를 읽고 싶으면 `planning/wardley-maps.md`
- 사업 모델 구조를 한 장으로 정리하는 것이면 `planning/business-model-canvas.md`
- 제품 로드맵 포맷 자체가 필요하면 `planning/roman-pichler.md`, `planning/aha.md`
- 개별 기술 선택의 결정 기록은 `architecture/architecture-decision-records.md`

## 무엇이 들어있나
Wardley 매핑의 핵심 주장은 "위치와 이동이 없는 그림은 지도가 아니라 다이어그램"이라는 것이다. 박스와 화살표는 관계만 보여주지만, 지도는 각 구성요소가 진화 축의 어디에 있고 어느 방향으로 움직이는지를 담기 때문에 전략적 판단(무엇을 직접 하고 무엇을 아웃소싱할지)을 가능하게 한다.
모든 구성요소는 시간이 지나면 오른쪽(더 상품화·유틸리티화된 상태)으로 이동한다는 전제가 깔린다. 따라서 지금 맞춤 제작해야 하는 것도 언젠가 사올 수 있게 되며, 반대로 이미 상품인 것을 직접 만드는 것은 대개 낭비다.
지도는 사용자 니즈에서 시작해 아래로 내려간다 — 내부 시스템 구조가 아니라 사용자에게 보이는 것이 맨 위에 온다.
이 사이트는 Wardley의 원저 내용을 챕터별 학습 자료·해설 형태로 재구성해 입문자가 따라 그릴 수 있게 만든 것이다.

## 인용 포인트
- "지도(map) vs 다이어그램" — 아키텍처 그림에 위치·이동 정보가 없다는 지적을 할 때.
- "모든 것은 상품화 쪽으로 이동한다" — 자체 개발 고집이나 반대로 조기 아웃소싱을 판단할 때의 축.
