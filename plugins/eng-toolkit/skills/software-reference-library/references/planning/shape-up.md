# Shape Up (Basecamp, 무료 웹북)

https://basecamp.com/shapeup/webbook

## 한 줄
"언제 끝나요?"를 "얼마를 쓸 건가요?"로 뒤집는 방법론 — 추정 대신 appetite(고정 예산)를 먼저 정하고, 6주 사이클 + 2주 쿨다운, 형태 잡기(shaping), 서킷 브레이커로 범위를 강제로 수렴시킨다.

## 페르소나
**스프린트는 도는데 뭐 하나 제대로 끝난 게 없는 팀의 리드.** 추정은 매번 틀리고, 못 끝낸 티켓은 다음 스프린트로 이월되며, 회고는 "다음엔 더 잘 추정하자"로 끝난다. 데일리·플래닝·리뷰라는 형식만 남고 그 회의들이 무엇을 결정하는지 아무도 설명하지 못한다.

## 이럴 때 연다
- 기간을 추정하는 방식 자체를 포기하고 예산 방식으로 바꾸려 할 때
- 기획이 너무 두루뭉술(무한정 커짐)하거나 너무 상세(개발 재량 없음)해서 매번 어긋날 때 — shaping이 그 중간 층을 정의한다
- 마감을 넘긴 프로젝트를 계속 연장할지 잘라낼지 판단 기준이 필요할 때 (서킷 브레이커)
- 인터럽트와 버그 대응이 계획을 다 잡아먹어서 쿨다운 개념을 도입하려 할 때

## 이럴 땐 아니다
- 스크럼의 공식 정의가 궁금하거나 사내 관행이 스크럼인지 판정하려는 것이면 `planning/the-scrum-guide.md`
- 애자일 원칙 원문이 필요하면 `planning/agile-manifesto.md`, 실무 가이드는 `planning/atlassian-agile-coach.md`
- Basecamp의 초기 제품 철학(더 오래된 책)은 `planning/getting-real.md`
- PDF 원본 배포용 랜딩은 `planning/shape-up-2.md`

## 무엇이 들어있나
가장 반직관적인 주장은 추정을 하지 말라는 것이다. 추정은 "이 일이 얼마나 걸릴까"를 묻지만, Shape Up은 "이 문제에 6주를 쓸 가치가 있는가"를 먼저 정하고(appetite) 그 예산 안에 들어가도록 범위를 깎는다. 시간이 변수가 아니라 상수다.
shaping은 기획과 설계 사이의 중간 해상도 작업이다. 와이어프레임처럼 세밀하지도, 한 줄 아이디어처럼 막연하지도 않게 — 핵심 요소와 경계(하지 않을 것)를 정한 상태로 팀에 넘긴다. 상세는 만드는 사람이 정한다.
백로그를 유지하지 않는다. 쌓아둔 티켓은 대부분 다시 논의될 뿐이므로, 매 사이클 베팅 테이블에서 다시 판단한다.
서킷 브레이커: 6주 안에 못 끝내면 자동 연장이 아니라 기본적으로 중단한다. 연장하려면 다음 베팅에서 다시 이겨야 한다.

## 인용 포인트
- "Fixed time, variable scope" — 일정 압박 논의를 범위 논의로 옮기는 한 문장.
- 서킷 브레이커 규칙 — 좀비 프로젝트를 종료시킬 근거로 그대로 쓸 수 있다.
- "백로그를 두지 않는다" — 관리되지 않는 티켓 더미를 정리할 때의 논거.
