# What Matters — OKR (John Doerr)

https://www.whatmatters.com/

## 한 줄
『Measure What Matters』 저자 John Doerr 가 운영하는 OKR 공식 자료 허브로, 책의 사례를 넘어 **OKR 사이클 각 단계별 템플릿·대화 가이드·캘린더 치트시트**와 도입 실패 사례에 답하는 Q&A 칼럼("Dear Andy")까지 실무 자산 위주로 제공한다.

## 페르소나
**분기 OKR 을 도입했는데 결국 "할 일 목록에 숫자만 붙인 것"이 되어버린 팀의 리드.** Objective 는 슬로건이고 Key Result 는 이미 하기로 정해진 작업의 완료율(예: "쿠폰 정책 개편 100% 완료")이라, 분기 말 리뷰가 성과 대화가 아니라 진척 보고가 된다. 무엇이 잘못됐는지 알려면 프레임워크 소개글이 아니라 **KR 을 다시 쓰는 실제 문장 예시와 체크인 대화 스크립트**가 필요하다.

## 이럴 때 연다
- KR 이 "완료/미완료"로만 판정되는 작업 목록이 되어버려서, 결과 지표형 KR 문장 예시를 찾아 다시 쓸 때
- 분기 중간 체크인 회의를 어떤 질문으로 굴려야 할지 정해진 진행 틀이 필요할 때
- 회사 OKR ↔ 팀 OKR 정렬(cascading vs. 자율 수립) 문제로 논쟁 중이고 원저자 쪽 입장을 근거로 대고 싶을 때
- OKR 을 인사평가와 연결할지 말지 결정해야 할 때
- 조직·업종별 실제 OKR 사례 문장이 필요할 때 (Stories / Examples 섹션)

## 이럴 땐 아니다
- 무료·간결한 도입 가이드와 흔한 실수 목록이면 `planning/google-re-work-okr.md` 로 충분하다. 이쪽은 책·강좌 생태계와 묶인 허브라 분량이 많다.
- 제품이 성공했는지 측정할 지표 체계 자체를 설계하는 문제라면 `planning/north-star-metric.md` 나 `planning/heart.md` 다. OKR 은 목표 설정 형식이지 지표 설계 방법론이 아니다.
- 지표 해석이 틀려서 잘못된 결론을 내는 게 문제라면 `planning/a-dirty-dozen-12.md` 로 간다.
- 백로그 우선순위를 매기는 문제라면 `planning/rice.md`. OKR 로 우선순위를 대체하려다 실패하는 게 흔한 오용이다.

## 무엇이 들어있나
사이트가 반복하는 주장은 "Ideas are easy, execution is everything" — 즉 OKR 의 가치는 좋은 목표를 발명하는 데 있지 않고 **매 분기 공개적으로 점수 매기고 버리는 실행 리듬**에 있다는 것이다.
구성은 크게 네 갈래다. (1) OKR 사이클 단계별 커스터마이즈 가능한 템플릿 5종과 대화 가이드·캘린더 치트시트, (2) 실제 조직들의 OKR 도입 사례를 다루는 Stories, (3) "Write Your First Objective", "Five Benefits of OKRs" 류의 짧은 영상 튜토리얼, (4) 도입 현장의 곤란한 질문에 답하는 "Dear Andy" Q&A 칼럼.
책 『Measure What Matters』 의 부속 사이트 성격이 강해서, 인텔·구글 계보의 OKR 서사가 배경으로 깔린다. Larry Page 의 추천사가 전면에 걸려 있는 식으로 마케팅 톤이 섞여 있다는 점은 감안해서 읽어야 한다.

## 인용 포인트
- OKR 사이클 단계별 템플릿과 대화 가이드는 사내 위키에 그대로 옮겨 팀 규칙으로 삼기 좋다 — 형식 논쟁을 원저자 자료로 종결시킬 수 있다.
- "Dear Andy" 칼럼은 "우리 팀만 이런가?" 싶은 도입 실패 패턴에 대한 답을 문답 형태로 담고 있어, 회고에서 근거로 인용하기 좋다.
