# User Story Mapping (Jeff Patton)

https://www.jpattonassociates.com/story-mapping/

## 한 줄
평평한 백로그 리스트를 사용자 여정(가로축) × 상세도(세로축)의 2차원 지도로 펼쳐, 릴리스 범위를 "위에서 가로로 얇게 자르는" 방식으로 정하는 기법의 원전 페이지.

## 페르소나
**MVP 범위를 자르라는 요구를 받았지만 무엇을 빼도 되는지 판단이 안 서는 기획자/PO.** 백로그는 우선순위 순으로 정렬된 한 줄짜리 리스트라서, 위에서부터 20개를 잘라도 그 조합이 실제로 동작하는 사용자 흐름인지 알 수 없다. 상위 항목만 만들었더니 주문은 되는데 결제가 안 되는 상태가 나온다.

## 이럴 때 연다
- MVP/1차 릴리스 범위를 자를 때 — 세로로 자르면 반쪽 제품, 가로로 자르면 쓸 수 있는 얇은 제품이 나온다
- 백로그가 평평한 리스트라 전체 그림이 안 보이고 누락된 단계가 계속 뒤늦게 발견될 때
- 신규 기능의 워크숍에서 개발·기획·디자인이 같은 흐름을 공유해야 할 때
- 주문→결제→배송 같은 여정 중 어느 단계가 통째로 비어 있는지 시각적으로 확인해야 할 때

## 이럴 땐 아니다
- 무엇을 만들지(어떤 문제를 풀지) 자체가 안 정해졌으면 `planning/teresa-torres-opportunity-solution-tree.md`
- 후보 간 순위를 숫자로 설명해야 하면 `planning/rice.md`
- 개별 스토리 작성 문법·INVEST가 필요하면 `planning/mountain-goat-software-user-stories.md`
- 기능이 아니라 비즈니스 목표에서 역으로 내려오는 매핑은 `planning/impact-mapping.md`
- 예제 기반 수용 기준을 뽑는 단계라면 `qa/example-mapping.md`

## 무엇이 들어있나
Patton은 스토리 매핑을 "제품을 통과하는 사용자의 여정을 이야기하는 것"이라고 정의한다. 도구가 아니라 대화가 본체라는 입장이다.
가로축은 시간 순서의 사용자 활동(백본), 세로축은 각 활동의 대안·상세 스토리다. 릴리스는 세로축을 가로지르는 수평 밴드로 정한다 — 그래야 각 릴리스가 끝에서 끝까지 동작하는 제품이 된다.
평평한 백로그가 문제인 이유를 명확히 한다: 리스트는 우선순위는 표현하지만 맥락과 전체 형태를 잃어버려서, 무엇이 빠졌는지 볼 수 없다.
"공유된 문서가 아니라 공유된 이해가 목표"라는 주장이 반복된다. 지도를 예쁘게 남기는 것보다 함께 그리는 과정이 산출물이라는 것.
페이지에서 전자책·슬라이드·요약 가이드 등 학습 자료를 함께 제공한다.

## 인용 포인트
- "세로로 자르지 말고 가로로 자르라" — MVP 범위 논쟁에서 즉시 쓸 수 있는 기준.
- "문서가 아니라 공유된 이해" — 기획서 품질 논쟁을 협업 방식 논쟁으로 옮길 때.

## 코드 예시

지도를 텍스트로 옮기면 "가로로 자른다"가 표의 행 하나가 된다 — 릴리스 1 행을 왼쪽부터 오른쪽까지 읽었을 때 끝에서 끝까지 이어지지 않으면 그건 릴리스가 아니다.

```markdown
# 스토리 맵 — 주문

## 백본 (가로축: 사용자 활동, 시간 순)
상품 찾기 → 장바구니 담기 → 결제하기 → 주문 확인 → 배송 추적

## 릴리스 밴드 (세로축을 가로지르는 수평 밴드)

| 릴리스 | 상품 찾기 | 장바구니 | 결제 | 주문 확인 | 배송 추적 |
|---|---|---|---|---|---|
| R1 (얇지만 끝까지) | 카테고리 목록 | 1종 담기 | 카드 1종 | 완료 화면 | 운송장 번호 표시 |
| R2 | 검색, 필터 | 수량 변경 | 간편결제 | 주문 내역 | 배송 단계 타임라인 |
| R3 | 추천 | 저장함 | 할부·쿠폰 | 취소·교환 | 도착 알림 |

## 자르는 규칙
- 세로로 자르지 않는다: "검색·필터·추천을 다 만들고 결제로 넘어간다" = 반쪽 제품
- R1 행에 빈 칸이 있으면 그 릴리스는 동작하지 않는다 (결제 없이 주문은 성립하지 않는다)
- 각 칸의 대안·상세는 그 칸 아래로 계속 늘어난다 — 늘어난 것을 아래 릴리스로 민다
```

표로 남기는 순간 이 자료가 경계한 것(공유된 문서만 남고 이해는 없는 상태)에 가까워진다 — 이 표는 함께 그린 결과의 기록이지, 워크숍을 대체하는 산출물이 아니다.
