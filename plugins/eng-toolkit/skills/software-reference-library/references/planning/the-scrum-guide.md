# The Scrum Guide

https://scrumguides.org/scrum-guide.html

## 한 줄
스크럼의 유일한 공식 정의(Schwaber·Sutherland, 2020판) — 사내 스크럼 논쟁의 대부분은 이 짧은 문서를 아무도 안 읽어서 생긴다.

## 페르소나
**"그건 스크럼이 아니다"라는 말이 오가는데 판정할 기준이 없는 팀의 스크럼 마스터/리드.** 데일리가 상태 보고 회의가 되고, PO가 두 명이고, 스프린트 중간에 범위가 계속 바뀐다. 각자 이전 회사 경험을 근거로 말해서 합의점이 없다.

## 이럴 때 연다
- 이벤트(스프린트 플래닝/데일리/리뷰/회고)의 목적과 시간 제한을 정확히 확인해야 할 때
- 역할(PO / 스크럼 마스터 / 개발자)의 책임 경계를 두고 다툴 때 — 특히 "PO가 우선순위를 최종 결정한다"의 근거
- 사내 관행이 스크럼인지 아닌지 판정해야 할 때 (도입 여부보다 "이름을 붙일 수 있는가"가 쟁점일 때)
- Definition of Done, Sprint Goal 같은 용어의 공식 정의가 필요할 때

## 이럴 땐 아니다
- 실무 운영 팁·안티패턴 설명이 필요하면 `planning/atlassian-agile-coach.md`
- 애자일의 가치·원칙 원문은 `planning/agile-manifesto.md`
- 추정이 계속 틀려서 방식 자체를 바꾸려는 것이면 `planning/shape-up.md`
- 사용자 스토리 작성법은 `planning/mountain-goat-software-user-stories.md`

## 무엇이 들어있나
20페이지도 안 되는 짧은 문서라는 것이 첫 번째로 놀라는 지점이다. 실무에서 "스크럼"이라 불리는 관행의 대부분(스토리 포인트, 벨로시티, 번다운 차트, 백로그 그루밍 회의)은 이 문서에 없다. 가이드는 이를 금지하지도 요구하지도 않는다.
2020판은 이전 판보다 더 얇아졌고, "개발팀" 대신 스크럼 팀 하나 안의 개발자들로 정리해 팀 안의 팀 구조를 없앴다. Product Goal, Sprint Goal, Definition of Done을 세 가지 확약(commitment)으로 명시한 것도 2020판의 변화다.
스크럼을 프로세스가 아니라 경험적 프로세스 제어(투명성·점검·적응)를 위한 틀로 규정한다. 이벤트가 존재하는 이유는 각각이 점검과 적응의 기회이기 때문이지, 회의를 채우기 위해서가 아니라고 못 박는다.
부분 도입에 대한 입장이 분명하다 — 요소를 골라 쓰는 것은 가능하지만 그 결과는 스크럼이 아니다.

## 인용 포인트
- "스토리 포인트도 벨로시티도 가이드에 없다" — 스크럼 도그마 논쟁을 끊는 데 효과적이다.
- 세 가지 확약(Product Goal / Sprint Goal / Definition of Done) — 스프린트가 목적 없이 티켓만 소화할 때 지적할 근거.
- 부분 도입은 스크럼이 아니라는 명시 — 형식만 남은 관행을 정리할 때.

## 코드 예시

2020판의 세 가지 확약만 남긴 스프린트 문서 — 벨로시티·번다운 칸이 없다는 것 자체가 이 문서의 논점이다.

```markdown
# Sprint 34 (2026-08-17 ~ 08-28)

## Product Goal (확약 1 — 여러 스프린트에 걸친 하나의 목표)
결제 실패로 이탈하는 주문을 절반으로 줄인다.

## Sprint Goal (확약 2 — 이번 스프린트 하나의 목적)
실패한 결제를 고객이 스스로 재시도할 수 있게 한다.
- 스프린트 중 범위는 협상 가능하지만 이 목적은 바뀌지 않는다.
- 항목을 다 못 끝내도 이 목적을 달성했으면 스프린트는 성공이다.

## Sprint Backlog (개발자들이 스스로 만든 계획)
- 실패 사유 4종 매핑
- 재시도 버튼
- 실패 이벤트 로깅

## Definition of Done (확약 3 — 팀 공통, 스프린트마다 바뀌지 않음)
- [ ] 코드 리뷰 승인
- [ ] 자동 테스트 통과
- [ ] 운영 배포 완료 (배포 안 된 것은 Done 이 아니다)
- [ ] 실패 이벤트가 분석 도구에서 조회된다

<!-- 스토리 포인트·벨로시티·번다운은 가이드에 없다. 쓰더라도 스크럼이라서 쓰는 게 아니다. -->
```

이 문서가 있어도 데일리가 상태 보고로 흐르면 형식만 남는다 — 가이드가 이벤트에 요구하는 것은 참석이 아니라 계획의 점검과 적응이다.
