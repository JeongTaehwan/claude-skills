# AFL (American Fuzzy Lop)

https://github.com/google/AFL

## 한 줄
입력을 무작위로 변형하면서 "새로운 코드 경로를 밟은 입력"만 살려 계속 변형해 나가는 커버리지 유도(coverage-guided) 퍼저의 원형. 지금 쓰이는 대부분의 퍼저가 이 아이디어의 후손이다.

## 페르소나
**바이너리 파서·이미지 디코더·프로토콜 파서처럼 신뢰할 수 없는 바이트열을 받는 네이티브 코드를 맡았는데, 단위 테스트로는 "생각해낸 입력"밖에 못 넣어 보는 엔지니어.** 크래시는 실제로 필드에서 나는데 재현 입력을 손으로 만들 수가 없다. 테스트 케이스를 더 쓰는 대신 입력 공간 자체를 기계가 훑게 만들고 싶은데, 퍼징이 어떻게 "그냥 랜덤"과 다른지 원리를 먼저 잡아야 한다.

## 이럴 때 연다
- C/C++ 등 네이티브 코드에 퍼징을 처음 도입해서, 계측(instrumentation) → 시드 코퍼스 → 변이 루프의 기본 골격을 이해해야 할 때
- "왜 랜덤 입력보다 커버리지 피드백이 압도적으로 나은가"를 팀에 설명해야 할 때
- 크래시 재현 케이스를 자동으로 최소화(minimize)하고 코퍼스를 정리하는 도구 체인을 찾을 때
- 퍼징 용어(코퍼스, 시드, 딕셔너리, 하네스)의 표준 정의가 필요할 때

## 이럴 땐 아니다
- 라이브러리 함수 단위로 인프로세스 퍼징 하네스를 붙이고 싶다면 `testing/libfuzzer.md`
- 오픈소스 프로젝트를 상시 퍼징 인프라에 태우는 운영 이야기라면 `testing/oss-fuzz.md`
- 퍼징 기법 전반의 분류·연구 지형이 필요하면 `testing/the-art-science-and-engineering-of-fuzzing-a-survey.md`
- 무작위 입력이되 "속성이 성립하는가"를 검증하고 싶은 거라면 퍼징이 아니라 속성 기반 테스트다 — `testing/hypothesis.md`, `testing/fast-check.md`

## 무엇이 들어있나
AFL의 핵심 주장은 단순하다. 입력을 무작위로 바꾸되, 실행 중 밟은 분기 커버리지를 해시로 기록해 **새로운 경로를 열어준 입력만 코퍼스에 남기고 그것을 다시 변형**하면, 순수 랜덤으로는 도달 불가능한 깊은 상태까지 진화적으로 들어간다는 것. 컴파일 시 계측을 심는 래퍼 컴파일러, 실행 속도를 위한 fork server, 크래시 트리아지와 케이스 최소화 도구가 함께 들어 있다.
현재 이 저장소는 아카이브 상태이며 활발한 개발은 AFL++로 이어졌다는 점을 함께 알고 인용해야 한다. 실무에서 새로 도입한다면 원조 AFL보다 후속 구현을 쓰는 것이 보통이다.

## 인용 포인트
- "퍼징 = 랜덤 입력"이라는 오해를 교정할 때: 랜덤이 아니라 커버리지 피드백을 적합도 함수로 쓰는 진화적 탐색이라는 점.
- 퍼징 도입을 제안할 때, 테스터가 케이스를 상상해내는 비용 대신 CPU 시간을 쓰는 접근이라는 프레이밍.

## 코드 예시

"계측 → 시드 코퍼스 → 변이 루프 → 크래시 최소화"라는 AFL 골격 전체를 명령 네 줄로 옮긴 것.

```bash
# 1) 커버리지 계측을 심어서 빌드한다 — 이게 랜덤 퍼징과 갈리는 지점
afl-gcc -o parser_fuzz parser.c

# 2) 시드 코퍼스: 유효한 입력 몇 개만 있으면 된다
mkdir -p seeds out
printf 'GET /index.html HTTP/1.0\r\n\r\n' > seeds/basic.txt

# 3) 변이 루프. @@ 는 AFL이 만든 임시 입력 파일 경로로 치환된다
#    (프로그램이 stdin을 읽으면 @@ 를 빼면 된다)
afl-fuzz -i seeds -o out -- ./parser_fuzz @@

# 4) 나온 크래시 입력을 사람이 읽을 크기로 줄인다
afl-tmin -i out/crashes/id:000000* -o crash_min.txt -- ./parser_fuzz @@

# 코퍼스가 불어나면 같은 커버리지를 내는 최소 집합으로 솎아낸다
afl-cmin -i out/queue -o corpus_min -- ./parser_fuzz @@
```

`afl-gcc` 로 빌드하지 않으면 커버리지 피드백이 없어 그냥 랜덤 퍼징이 되고, AFL은 이를 경고만 하고 계속 돈다. 또 이 저장소는 아카이브 상태라 실무 도입은 AFL++(`afl-clang-fast` 등) 쪽이 보통이다.
