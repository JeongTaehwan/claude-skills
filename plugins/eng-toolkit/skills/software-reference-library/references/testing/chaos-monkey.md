# Chaos Monkey (Netflix)

https://github.com/Netflix/chaosmonkey

## 한 줄
운영 환경에서 인스턴스를 무작위로 종료시켜 "한 대 죽어도 서비스가 살아남는가"를 상시 검증하는 원조 카오스 엔지니어링 도구 — 개념 선언이 아니라 실제로 돌아갔던 구현물이다.

## 페르소나
**장애 대응 문서에는 "이중화되어 있음"이라고 써 있지만 실제로 한 대를 내려 본 적은 없는 팀에 속한 사람.** 인스턴스 한 대가 빠졌을 때 커넥션 풀이 어떻게 되는지, 큐 컨슈머가 재분배되는지, 헬스체크가 실제로 트래픽을 빼는지가 전부 "그럴 것이다" 수준이다. 카오스 실험을 제안하고 싶지만 경영진에게 "일부러 서버를 죽인다"를 설명할 실물 선례가 필요하다.

## 이럴 때 연다
- 이중화·자동 복구가 문서상 주장인지 실제 동작인지 검증할 방법을 찾을 때
- 카오스 엔지니어링 도입을 제안하면서 실제 운영 사례를 근거로 들어야 할 때
- 인스턴스 종료 실험의 적용 범위·스케줄·제외 규칙을 어떻게 설계했는지 참고할 때
- 장애 훈련(게임데이) 시나리오를 만들 때 가장 단순한 시작점을 찾을 때

## 이럴 땐 아니다
- 실험을 어떤 원칙과 순서로 설계해야 하는지가 먼저면 `infrastructure/principles-of-chaos-engineering.md`
- 도구 지형 전반을 훑고 싶으면 `qa/awesome-chaos-engineering.md`
- 부하를 견디는지가 문제라면 카오스가 아니라 부하 도구 — `testing/k6-io-docs.md`, `testing/apache-jmeter.md`

## 무엇이 들어있나
Chaos Monkey가 하는 일 자체는 단순하다. 지정된 그룹 안에서 인스턴스를 골라 종료시킨다. 중요한 것은 이 단순함을 운영에서 견디게 만든 주변 장치들이다 — 업무 시간대에만 돌려 사람이 대응할 수 있게 하고, 그룹 단위로 참여 여부와 빈도를 설정하며, 종료 이력을 남긴다. 즉 "무작위 파괴"가 아니라 **관측 가능한 시간대에 통제된 강도로 반복되는 실험**이다.

이 도구가 실질적으로 강제하는 것은 복구 자동화다. 인스턴스가 정기적으로 사라지는 환경에서는 수동 복구 절차가 버티지 못하므로, 오토스케일링·헬스체크·상태 비저장 설계가 선택이 아니라 전제가 된다. 도구가 결함을 찾아 주는 것이 아니라, 결함이 쌓이지 못하게 만드는 압력으로 작동한다.

지금 시점에서는 이 저장소 자체를 그대로 도입하기보다(현재는 Spinnaker 연동 전제이며 활발히 개발되지 않는다) **가장 작은 카오스 실험의 원형**으로 읽는 편이 낫다. 커머스라면 결제 콜백을 처리하는 컨슈머 한 대를 내려 보고 미처리 메시지가 재분배되는지 확인하는 것이 여기서 파생되는 첫 실험이다.

## 인용 포인트
- 업무 시간대에만 실행한다는 설계 — "운영에서 일부러 죽인다"에 대한 반발을 통제 가능한 실험으로 바꿔 설명할 때의 핵심 디테일.
- 정기적 인스턴스 종료가 복구 자동화를 강제한다는 인과 — 카오스 도입의 목적이 장애 발견이 아니라 아키텍처 압력임을 설명하는 논거.

## 코드 예시

"무작위 파괴가 아니라 통제된 실험"이라는 주장이 설정 파일 어디에 박혀 있는지 — 업무 시간대 제한과 leashed 모드.

```toml
# chaosmonkey.toml
[chaosmonkey]
enabled = true

# leashed = true 면 "죽였을 것이다"만 기록하고 실제로는 종료하지 않는다.
# 도입 첫 주는 여기서 시작해 대상 목록이 예상과 맞는지 먼저 본다.
leashed = true

# 스케줄러가 하루치 종료 계획을 미리 뽑는다
schedule_enabled = true

# 사람이 대응할 수 있는 시간대에만 실행 — 반발을 가라앉히는 핵심 디테일
start_hour = 10
end_hour = 15
time_zone = "Asia/Seoul"

# 참여 대상은 계정 단위로 옵트인
accounts = ["prod"]
```

이 설정은 "언제 죽일지"만 통제할 뿐, 죽은 뒤 무엇을 정상으로 볼지는 정하지 않는다 — 실험 전에 정상 상태 지표(주문 성공률, 미처리 메시지 수)를 먼저 정해 두지 않으면 종료 로그만 쌓이고 배우는 게 없다.
