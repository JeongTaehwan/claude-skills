# Locust

https://locust.io/

## 한 줄
가상 사용자를 설정 파일이 아니라 **평범한 파이썬 코드**로 기술하는 부하 테스트 도구 — 사용자마다 상태를 들고 분기·반복하는 시나리오를 그냥 파이썬 클래스로 쓴다.

## 페르소나
**부하 도구의 시나리오 표현력이 실제 사용자 흐름을 못 따라가서 막힌 엔지니어.** 로그인 → 장바구니 담기 → 쿠폰 적용 실패 시 다른 쿠폰 재시도 → 결제처럼, 앞 응답에 따라 다음 요청이 달라지는 흐름을 GUI 나 선언형 스크립트로 옮기다 보니 원래 검증하려던 것과 다른 트래픽을 쏘고 있다. 필요한 건 조건문과 상태를 자연스럽게 쓸 수 있는 시나리오 언어다.

## 이럴 때 연다
- 응답에 따라 분기하는 다단계 사용자 여정을 부하로 재현해야 할 때
- 팀의 주 언어가 파이썬이라 시나리오를 애플리케이션 코드처럼 리뷰·테스트하고 싶을 때
- 사용자 유형별 비중(구매자 10%, 조회자 90%)을 가중치로 섞어야 할 때
- 한 대로는 부족해 여러 워커로 분산 부하를 걸어야 할 때

## 이럴 땐 아니다
- CI 에서 임계값 기반 자동 합불 판정이 주 목적이면 `testing/k6-io-docs.md`
- JVM 기반 팀에서 고성능 시나리오 DSL 이 필요하면 `testing/gatling.md`
- 사내에 이미 GUI 기반 테스트 계획 자산이 쌓여 있다면 `testing/apache-jmeter.md`

## 무엇이 들어있나
모델은 단순하다. `User` 클래스를 상속하고 `@task` 데코레이터로 동작을 붙이면, 그 클래스의 인스턴스 하나가 가상 사용자 하나가 된다. task 에 가중치를 주어 행동 분포를 만들고, `wait_time` 으로 사용자 사이의 대기(생각 시간)를 준다. `on_start` 에서 로그인 같은 준비를 하고, 사용자 인스턴스에 상태(토큰, 장바구니 ID)를 그대로 들고 다닌다.

실행 측면에서는 gevent 기반 코루틴으로 한 프로세스가 수많은 사용자를 흉내 내고, 마스터/워커 구조로 수평 확장한다. 실시간 통계를 보여 주는 웹 UI 가 기본으로 붙고, `--headless` 로 CI 실행도 가능하다. HTTP 가 기본이지만 클라이언트를 직접 감싸면 다른 프로토콜에도 쓸 수 있다.

주의점은 부하 생성기 자체가 파이썬이라는 것이다. 요청당 계산이 무거운 시나리오에서는 대상 서버보다 로드 제너레이터가 먼저 한계에 닿을 수 있어, 워커 수와 CPU 사용률을 측정해 두지 않으면 결과 해석이 통째로 틀어진다.

## 인용 포인트
- "시나리오가 코드면 리뷰·재사용·버전 관리가 된다" — 부하 스크립트를 별도 도구 자산이 아니라 저장소 코드로 옮기자는 제안의 근거.
