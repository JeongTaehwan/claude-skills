# FTC — CAN-SPAM Act 사업자 준수 가이드

https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business

## 한 줄
미국 상업용 이메일의 법정 최소 요건을 규제기관이 직접 7개 규칙으로 정리한 문서 — **동의 없이 보내는 것은 허용하되(옵트아웃 체계), 발신자 신원·구독 해지·물리적 주소를 강제**하며, 위반 시 이메일 한 통이 각각 별개의 위반이 된다.

## 페르소나
**뉴스레터 발송 기능을 만들면서 "구독 해지 링크는 나중에 붙이자"고 백로그로 미룬 개발자.** 이 결정이 기능 우선순위 문제가 아니라 법적 요건 문제라는 것을 모르는 상태. 그리고 발송 대행사를 쓰면 책임이 넘어간다고 생각하는 것도 흔한 오해 — 가이드는 **대행을 맡겨도 광고 주체의 책임이 사라지지 않는다**고 명시한다.

또 하나 — **주문 확인 메일 하단에 신상품 배너를 넣어 달라는 요청을 받은 개발자.** 순수 트랜잭션 메일과 광고성 메일은 적용 규칙이 다른데, 마케팅 콘텐츠를 섞는 순간 그 메일의 "주된 목적(primary purpose)"이 재분류될 수 있다. 무해해 보이는 배너 하나가 메일의 법적 성격을 바꾼다.

## 이럴 때 연다
- 마케팅 이메일 발송 기능의 요구사항 목록을 확정할 때
- 구독 해지 흐름(링크·처리 기한·재구독 요구 금지)을 설계할 때
- 트랜잭션 메일에 마케팅 콘텐츠를 섞자는 요청을 판단할 때
- 발송 대행사·제휴 마케터를 쓸 때 책임 범위를 정할 때
- 발신자 정보·제목·From 주소 정책을 정할 때
- 글로벌 서비스라 미국·EU·한국의 요건 차이를 정리해야 할 때

## 이럴 땐 아니다
- 미국 밖 규제는 이 문서 범위가 아니다 — EU 는 GDPR/ePrivacy 의 사전 동의 원칙, 한국은 정보통신망법의 사전 동의·"(광고)" 표기·야간 전송 별도 동의가 각각 별개로 적용된다. **셋 중 가장 엄격한 기준을 따라야 하며, CAN-SPAM 만 지켜서는 한국·EU 요건을 충족하지 못한다**
- 발송·바운스·구독 상태의 기술적 처리는 `marketing/postmark-developer-docs.md`
- 이메일 본문 제작은 `marketing/mjml-email-framework.md`, `marketing/react-email-docs.md`
- 이메일 성과 측정·귀속은 `marketing/utm-campaign-url-tagging.md`, `marketing/segment-analytics-spec.md`
- 개인정보 저장·처리의 보안 요건은 `security/owasp-top-10.md`
- 이 문서는 법률 자문이 아니다 — 실제 적용은 법무 검토가 필요하다

## 무엇이 들어있나
가이드는 **7개 규칙**으로 요건을 정리한다.

1. **헤더 정보를 거짓·오인 유발적으로 쓰지 말 것.** `From`, `To`, `Reply-To`, 그리고 발신 도메인과 라우팅 정보가 발신자를 정확히 식별해야 한다.
2. **제목을 기만적으로 쓰지 말 것.** 제목이 본문 내용을 반영해야 한다.
3. **광고임을 밝힐 것.** 메시지가 광고라는 사실을 명확하고 눈에 띄게 표시해야 한다(표현 방식은 재량).
4. **유효한 물리적 우편 주소를 표시할 것.** 현재 유효한 사업장 주소 또는 등록된 사서함. **이메일 푸터에 회사 주소가 들어가는 이유가 이것**이며, 디자인상 지저분해 보인다는 이유로 뺄 수 있는 항목이 아니다.
5. **수신 거부 방법을 알릴 것.** 명확하고 눈에 띄게, 그리고 일반 수신자가 알아볼 수 있게.
6. **수신 거부 요청을 신속히 처리할 것.** 가이드가 규정하는 구체적 제약이 많고, 여기가 개발에서 가장 자주 틀리는 지점이다.
   - 수신 거부 수단은 발송 후 **최소 30일간** 동작해야 한다
   - 요청은 **10영업일 이내** 처리해야 한다
   - 수수료를 받거나, 이메일 주소 외의 정보를 요구하거나, **로그인을 요구하거나, 여러 페이지를 거치게 만들면 안 된다**
   - 해지한 주소를 판매·양도할 수 없다(준수를 위한 억제 목록 용도 제외)
7. **대행 업체의 행위를 감시할 것.** 발송을 외주해도 **광고 주체와 발송자 양쪽 모두 법적 책임을 진다.** 계약으로 떠넘겨지지 않는다.

**적용 범위와 "주된 목적" 판정.** 법은 상업용 메시지(상품·서비스의 광고·판촉이 주된 목적)에 적용된다. 이미 성립된 거래에 관한 정보만 담은 **거래·관계형 메시지(transactional or relationship message)** 는 위 요건 중 상당수가 면제되지만, **1번(헤더 정보를 거짓으로 쓰지 말 것)은 여전히 적용된다.** 상업 콘텐츠와 거래 콘텐츠가 섞이면 주된 목적이 무엇인지로 판정한다 — 주문 확인 메일에 프로모션을 넣는 결정이 법적 성격을 바꿀 수 있다는 것이 여기서 나온다.

**B2B 예외는 없다.** 법은 "대량 발송"에만 적용되는 것이 아니며 **모든 상업용 이메일**에 적용된다. 사업자 대상 메일도 포함된다.

**제재.** 요건을 위반한 이메일은 **한 통 한 통이 별개의 위반**으로 취급되며 각각에 대해 과징금이 부과될 수 있다. 구체적 금액은 물가 연동으로 조정되므로 원문에서 현재 액수를 확인해야 한다. 허위 헤더나 주소 수집(하비스팅) 같은 행위에는 형사 처벌 조항도 있다.

## 인용 포인트
- 구독 해지 링크를 다음 스프린트로 미루자는 결정을 되돌릴 때 — 기능이 아니라 법정 요건이며 위반이 통당 계산된다는 점을 든다.
- 구독 해지에 로그인을 요구하는 구현을 반려할 때, 로그인 요구·다단계 절차 금지 조항을 그대로 인용한다.
- 이메일 푸터에서 회사 주소를 빼자는 디자인 요구를 막을 때 4번 규칙을 근거로 쓴다.
- 주문 확인 메일에 프로모션 배너를 넣자는 요청을 검토할 때, 주된 목적 판정이 메일의 법적 분류를 바꾼다는 점을 리스크로 제시한다.
- 발송을 대행사에 맡기니 우리 책임이 아니라는 주장을 반박할 때 7번 규칙을 인용한다.
- 해지 처리 SLA(10영업일)와 해지 수단 유효기간(30일)을 시스템 요구사항으로 명문화할 때.
- 글로벌 서비스의 이메일 정책을 정할 때 — CAN-SPAM 은 옵트아웃 체계이지만 한국·EU 는 사전 동의 체계라는 대비를 설계 근거로 든다.

## 코드 예시

"수수료·추가 정보·로그인 없이, 한 번의 동작으로 해지되어야 한다"는 6번 규칙을, 원클릭 구독 해지 헤더(RFC 8058)와 푸터로 옮긴 것이다.

```http
List-Unsubscribe: <https://example.com/u/9f3a1c2e>, <mailto:unsubscribe@example.com?subject=unsub-9f3a1c2e>
List-Unsubscribe-Post: List-Unsubscribe=One-Click
```

```html
<!-- 광고성 메일 푸터의 법정 최소 구성 -->
<div style="font-size:12px;color:#6b7280">
  <!-- 3. 광고임을 밝힌다 (한국은 제목에 "(광고)" 표기가 별도 요건) -->
  <p>이 메일은 광고입니다.</p>

  <!-- 4. 유효한 물리적 우편 주소 -->
  <p>Example Apparel · 서울특별시 강남구 테헤란로 1, 06232</p>

  <!-- 5·6. 로그인·추가 정보 요구 없이 한 번의 클릭으로 해지되는 링크 -->
  <p><a href="https://example.com/u/9f3a1c2e">수신거부(구독 해지)</a></p>
</div>
```

```sql
-- 해지 요청은 즉시 억제 목록에 반영하고, 발송 쿼리가 항상 이 목록을 참조하게 한다.
INSERT INTO email_suppressions (email, reason, created_at)
VALUES ('customer@example.com', 'unsubscribe', now())
ON CONFLICT (email) DO NOTHING;

SELECT u.email FROM users u
LEFT JOIN email_suppressions s ON s.email = u.email
WHERE u.marketing_opt_in = true AND s.email IS NULL;  -- 억제 확인을 발송 경로에 박아 둔다
```

이 코드가 감추는 것: 억제 목록을 발송 직전에 조회하는 것만으로는 부족하다 — 큐에 이미 들어간 메시지, 재시도 대기 중인 메시지, 다른 시스템이 만든 발송 경로가 각각 이 게이트를 우회할 수 있으므로, 확인 지점은 쿼리가 아니라 발송 어댑터 한 곳으로 모아야 한다.
