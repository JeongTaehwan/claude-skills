# Growth Loops are the New Funnels (Brian Balfour, Reforge)

https://www.reforge.com/blog/growth-loops

## 한 줄
Brian Balfour(Reforge 창업자, 전 HubSpot VP Growth) 외, 2018 — 성장을 위에서 아래로 흘러내리는 **깔때기가 아니라, 산출물이 다시 입력으로 되돌아가는 닫힌 루프**로 모델링해야 하며, 그래야 복리로 자라는 성장과 계속 돈을 부어야 유지되는 성장을 구분할 수 있다는 글.

## 페르소나
**매달 광고비를 넣는 만큼만 사용자가 늘고, 광고를 끄면 유입이 그대로 0으로 수렴하는 서비스를 운영하는 그로스 담당자.** 깔때기 단계별 전환율은 다 개선했는데 성장의 형태 자체는 선형이다. 지금 얻은 사용자가 **다음 사용자를 데려오는 경로**가 제품 안에 있는지, 없다면 어디에 만들 수 있는지를 구조로 그려야 하는 상황이다.

## 이럴 때 연다
- 성장이 광고비에 정비례하고 자생적 유입이 없을 때 구조를 다시 그리려 할 때
- "우리 제품은 어떻게 성장하는가"를 한 장 그림으로 경영진에 설명해야 할 때
- 여러 성장 이니셔티브 중 무엇이 복리 효과가 있는지 우선순위를 가릴 때
- 콘텐츠·UGC·바이럴·세일즈 중 어떤 종류의 루프를 만들지 결정할 때
- 깔때기 지표(단계 전환율)만으로 판단이 안 될 때 루프 단위 지표를 새로 정의할 때
- 성장 조직의 팀 구성과 목표를 루프별로 나누려 할 때

## 이럴 땐 아니다
- 단계별 지표의 기본 틀이 아직 없다면 `marketing/aarrr-startup-metrics-for-pirates.md`
- 획득 **채널 후보**를 훑는 문제라면 `marketing/traction-weinberg-mares.md`
- 제품 사용 자체가 구매를 이끄는 모델(무료 체험·셀프서브)의 설계는 `marketing/product-led-growth-wes-bush.md`
- 루프의 리텐션 축을 데이터로 검증하려면 `marketing/cohort-retention-sequoia.md`
- 유료 루프의 경제성(회수 기간)은 `marketing/cost-of-customer-acquisition-skok.md`
- 조직 전체를 한 지표로 정렬하는 논의는 `planning/north-star-metric.md`

## 무엇이 들어있나
글의 출발점은 깔때기 모델의 한계다. 깔때기는 "방문 → 가입 → 활성화 → 결제"처럼 **한 방향으로 끝나는** 흐름이라, 그 끝에서 나온 결과가 다시 처음의 입력이 되는 관계를 표현하지 못한다. 그래서 깔때기만 보면 모든 성장이 "입구에 더 많이 넣는" 문제로 환원되고, 채널 비용이 오르면 성장도 멈춘다.

루프는 이렇게 쓴다 — **입력 → 행동 → 산출 → 그 산출이 다시 입력이 됨.** 예를 들어 UGC/SEO 루프는 "사용자가 콘텐츠를 만든다 → 검색에 노출된다 → 새 방문자가 온다 → 그중 일부가 가입해 다시 콘텐츠를 만든다"로 닫힌다. 바이럴 루프는 초대·공유가, 유료 루프는 수익 재투자가 되돌아오는 경로다. 글은 루프를 크게 세 종류(신규 사용자 루프, 참여 루프, 수익 루프)로 나누고, 실제 회사의 성장은 대개 **하나의 지배적 루프**로 설명된다고 본다.

실무적으로 가장 쓸모 있는 대목은 관점의 전환이 만드는 세 가지 결과다. 첫째, **일이 어디에 쌓이는지가 달라진다** — 루프의 한 지점을 개선하면 그 효과가 다음 사이클의 입력으로 넘어가 복리가 되지만, 깔때기의 한 단계 개선은 그 단계에서 끝난다. 둘째, **팀 구조가 달라진다** — 채널별 팀이 아니라 루프별 팀이 자연스러워진다. 셋째, **지표가 달라진다** — 단계 전환율 대신 "한 사이클이 도는 데 걸리는 시간"과 "기존 사용자 1명이 다음 사이클에 만드는 신규 사용자 수"가 핵심 지표가 된다.

Reforge 블로그의 이 글은 무료로 읽을 수 있고, 같은 시리즈의 다른 글들(Casey Winters, Kevin Kwok, Andrew Chen 공동 작업)이 이어진다. Reforge 의 유료 프로그램 홍보가 함께 붙어 있는 상업 블로그라는 점은 감안하고 읽는다.

## 인용 포인트
- 광고비 비례 성장에서 벗어나자는 제안에서, 선형 깔때기와 복리 루프의 구조 차이를 근거로 든다.
- 성장 로드맵 우선순위를 정할 때 "이 개선이 루프 안에 있는가, 밖에 있는가"라는 판정 기준으로.
- 채널 중심 조직을 루프 중심으로 재편하자는 제안의 논거.
- 지표 리뷰에서 단계 전환율만으로는 성장 형태를 판별할 수 없다는 지적을 세울 때.

## 코드 예시

루프를 지표로 옮기면 두 숫자로 압축된다 — **사이클 시간**과 **루프 계수**(기존 사용자 1명이 다음 사이클에 만들어 낸 신규 사용자 수). 초대 기반 루프의 최소 계산.

```sql
-- 주 단위 루프 계수: 이번 주 가입자 중 초대로 들어온 수 / 직전 주까지의 활성 사용자 수
WITH weekly_new AS (
  SELECT DATE_TRUNC('week', created_at) AS wk,
         COUNT(*) FILTER (WHERE referred_by_user_id IS NOT NULL) AS invited_signups,
         COUNT(*)                                                AS total_signups
  FROM users GROUP BY 1
),
weekly_active AS (
  SELECT DATE_TRUNC('week', event_at) AS wk, COUNT(DISTINCT user_id) AS active_users
  FROM events WHERE event_name = 'app_opened' GROUP BY 1
)
SELECT n.wk,
       a_prev.active_users                                        AS prior_week_active,
       n.invited_signups,
       n.total_signups,
       ROUND(n.invited_signups::numeric / NULLIF(a_prev.active_users, 0), 4) AS loop_factor,
       ROUND(100.0 * n.invited_signups / NULLIF(n.total_signups, 0), 1)      AS invited_share_pct
FROM weekly_new n
LEFT JOIN weekly_active a_prev ON a_prev.wk = n.wk - INTERVAL '1 week'
ORDER BY n.wk;
```

`loop_factor` 는 상관 지표이지 인과가 아니다 — 초대 링크를 타고 왔지만 어차피 광고로도 왔을 사람이 섞이므로, 루프의 실제 증분은 홀드아웃 실험으로만 갈린다.
