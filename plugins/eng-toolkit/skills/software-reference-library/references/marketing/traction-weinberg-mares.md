# Traction (Gabriel Weinberg & Justin Mares)

https://www.penguin.co.uk/books/181725/traction-by-weinberg-gabriel/9780241242537

## 한 줄
Gabriel Weinberg(DuckDuckGo 창업자) & Justin Mares, 2015 — 고객 획득 채널을 **19가지로 목록화**하고, 그중 어디에 걸지를 감이 아니라 "불스아이(Bullseye)"라는 선별 절차로 정하게 만드는 실무서.

## 페르소나
**제품은 나왔고 초기 사용자도 조금 있는데, 다음 달 마케팅 계획이 "인스타랑 블로그 좀 해 보고, 광고도 조금 돌려 보자"인 팀.** 예산도 인력도 한 채널을 제대로 파기에도 빠듯한데 여섯 개를 얕게 건드리고 있고, 3개월 뒤 무엇이 되고 무엇이 안 됐는지 판정할 기준도 없다. **채널 후보를 빠짐없이 나열하고, 싸게 테스트해 하나로 좁히는 절차**가 필요한 상황이다.

## 이럴 때 연다
- 초기 고객 획득 채널을 처음 정할 때, 후보를 빠짐없이 훑고 싶을 때
- "우리 업종은 원래 이 채널"이라는 관성을 깨고 후보를 넓혀야 할 때
- 여러 채널을 동시에 얕게 돌리는 상태를 정리해 하나에 집중시켜야 할 때
- 채널 테스트의 예산·기간·성공 기준을 사전에 못 박아야 할 때
- 잘 되던 채널이 포화돼 다음 채널을 찾아야 할 때
- 마케팅 인력이 없는 엔지니어 중심 팀에 획득 실행 절차를 넘길 때

## 이럴 땐 아니다
- 획득 이후 **활성화·리텐션·수익화**까지 단계 전체의 지표 틀은 `marketing/aarrr-startup-metrics-for-pirates.md`
- 채널이 아니라 제품 자체가 성장을 만드는 구조를 원하면 `marketing/growth-loops-are-the-new-funnels.md`, `marketing/product-led-growth-wes-bush.md`
- 채널 단위 경제성(CAC·회수 기간) 계산은 `marketing/cost-of-customer-acquisition-skok.md`
- 무엇을 말할지(포지셔닝·카테고리)가 안 정해졌다면 `marketing/obviously-awesome-april-dunford.md`
- 검색 채널의 실무 규범은 `marketing/google-search-essentials.md`
- 광고 예산의 브랜드/퍼포먼스 배분은 `marketing/binet-field-media-in-focus.md`

## 무엇이 들어있나
책의 뼈대는 두 가지다. 첫째, **19개 채널 목록** — 바이럴 마케팅, PR, 언컨벤셔널 PR, SEM(검색 광고), 소셜·디스플레이 광고, 오프라인 광고, SEO, 콘텐츠 마케팅, 이메일 마케팅, 엔지니어링 애즈 마케팅(무료 도구 제공), 타깃 블로그, 사업 개발, 세일즈, 제휴 프로그램, 기존 플랫폼(앱스토어·확장 프로그램 등), 트레이드쇼, 오프라인 이벤트, 강연, 커뮤니티 구축. 각 채널마다 짧은 설명과 실무자 인터뷰가 붙는다. 목록의 가치는 완전성에 있다 — **평소 떠올리지 않는 채널을 강제로 검토하게 만드는 체크리스트**로 쓴다.

둘째, **불스아이 프레임워크** — 세 겹의 원으로 채널을 좁히는 절차다. 바깥 원: 19개 전부를 놓고 "이게 가능할까"를 브레인스토밍한다. 중간 원: 그중 유망한 소수(대략 서너 개)를 골라 **값싸고 빠른 테스트**를 병렬로 돌린다. 여기서 테스트의 목적은 성과 극대화가 아니라 "이 채널이 우리에게 작동할 가능성이 있는가"의 판정이다. 안쪽 원: 승자 하나를 골라 자원을 몰아 그 채널을 한계까지 민다.

저자들이 반복해서 강조하는 규율이 몇 개 있다. 채널 테스트는 **사전에 비용·기간·판정 기준을 정해 놓고** 시작한다. 제품 개발과 트랙션 확보에 시간을 절반씩 쓴다(50% 룰). 그리고 채널은 포화된다 — 지금 잘 되는 채널이 계속 잘 되리라 가정하지 말고 다음 후보를 계속 테스트한다.

책은 유료이며, 위 링크는 출판사(Penguin) 공식 페이지다. 사례가 2010년대 중반 미국 스타트업 중심이라 개별 전술의 수치는 낡았다 — **절차와 채널 목록**을 가져다 쓰고 수치는 자기 데이터로 대체하는 것이 옳은 사용법이다.

## 인용 포인트
- 채널 계획 리뷰에서 "후보를 다 훑었는가"를 묻는 근거 — 19개 목록을 체크리스트로 제시한다.
- 여러 채널 동시 집행을 하나로 좁히자는 제안에 불스아이의 3단 구조를 절차로 든다.
- 채널 테스트 시작 전에 판정 기준을 문서에 못 박자는 요구의 논거.
- 제품 개발에만 시간을 쓰는 팀에 획득 활동의 시간 배분을 요구할 때(50% 룰).

## 코드 예시

불스아이의 중간 원 — 여러 채널을 **같은 판정 기준으로** 비교하려면 채널별 획득 비용과 전환을 한 표에 놓아야 한다.

```sql
-- 채널 테스트 판정표: 지출, 신규 가입, 유료 전환, CAC
WITH signups AS (
  SELECT acquisition_channel AS channel,
         COUNT(*)                                          AS signups,
         COUNT(*) FILTER (WHERE first_paid_at IS NOT NULL)  AS paid_users
  FROM users
  WHERE created_at >= DATE '2026-06-01' AND created_at < DATE '2026-07-01'
  GROUP BY 1
),
spend AS (
  SELECT channel, SUM(spend) AS spend
  FROM ad_spend
  WHERE spend_date >= DATE '2026-06-01' AND spend_date < DATE '2026-07-01'
  GROUP BY 1
)
SELECT s.channel, sp.spend, s.signups, s.paid_users,
       ROUND(100.0 * s.paid_users / NULLIF(s.signups, 0), 1) AS paid_conv_pct,
       ROUND(sp.spend / NULLIF(s.paid_users, 0))             AS cac_per_paid_user
FROM signups s
LEFT JOIN spend sp USING (channel)
ORDER BY cac_per_paid_user NULLS LAST;
```

CAC 가 낮은 채널이 곧 승자는 아니다 — 이 표에는 **채널의 규모 한계**(그 CAC 로 얼마까지 더 살 수 있는가)가 빠져 있고, 불스아이의 안쪽 원 결정은 사실 그 규모 한계로 갈린다.
