# ByteByteGo — 시스템 디자인

https://bytebytego.com/

## 한 줄
Alex Xu의 『System Design Interview』에서 출발한 상용 학습 플랫폼 — 시스템 설계를 "면접에서 45분 안에 설명 가능한 형태"로 압축한 시각 자료가 본체이고, 무료로 열려 있는 건 주로 뉴스레터와 미리보기 챕터다.

## 페르소나
**이직을 준비하면서, 매일 만지는 주문·결제 시스템은 설명할 수 있는데 "URL 단축기를 설계해보세요" 같은 백지 상태 질문 앞에서 어디부터 말해야 할지 몰라 얼어붙는 백엔드 엔지니어.** 실무에서는 이미 정해진 구조 위에 기능을 얹어 왔기 때문에, 요구사항 정리 → 개략 추정 → 하이레벨 설계 → 병목 심화라는 *진행 순서* 자체를 연습해본 적이 없다. 또는 사내에서 시스템 구조를 비개발 직군에게 설명할 그림이 필요한데, 논문식 자료는 너무 무겁고 블로그 글은 근거가 얕아 중간이 없는 상황.

## 이럴 때 연다
- 시스템 디자인 면접을 준비하며, 답변의 뼈대(요구사항 명세 → 용량 추정 → 컴포넌트 배치 → 스케일링)를 몸에 익히고 싶을 때
- 캐시·큐·샤딩·CDN 같은 구성요소가 "왜 거기 있는지"를 한 장 그림으로 다시 정리하고 싶을 때
- 팀 온보딩 자료나 설계 리뷰 슬라이드에 쓸, 설명이 붙은 아키텍처 다이어그램의 어법을 참고할 때
- 알림 시스템·결제 시스템·피드처럼 전형적인 시스템의 표준 구성이 어떤 모양인지 빠르게 감을 잡을 때

## 이럴 땐 아니다
- 무료로 같은 범위를 훑고 싶고 오픈소스 텍스트가 편하면 `architecture/system-design-primer.md` — 내용 축이 거의 겹치고 이쪽은 GitHub 저장소라 비용이 없다
- 면접용 요약이 아니라 *왜 그 설계가 맞는지*의 1차 근거가 필요하면 `architecture/designing-data-intensive-applications.md`
- 실제 운영에서 무너지는 지점(재시도 폭주, 과부하, 정적 안정성)을 다루려면 `architecture/amazon-builders-library.md`
- 다이어그램의 추상화 레벨을 규율 있게 나누는 표기법이 목적이면 `architecture/c4-model.md`

## 무엇이 들어있나
현재 사이트는 단일 블로그가 아니라 유료 코스 묶음 형태다. 이력서, 코딩 패턴, 시스템 디자인 면접, 행동 면접, 객체지향 설계, ML 시스템 디자인, 모바일 시스템 디자인, 생성형 AI 시스템 디자인 등 면접 단계별 트랙으로 구성되어 있고, 무료 미리보기 챕터와 뉴스레터가 진입점이다.

강점과 한계가 같은 곳에서 나온다. 모든 개념을 다이어그램 한 장 + 짧은 설명으로 환원하기 때문에 습득이 빠르지만, 트레이드오프의 근거(어떤 논문·어떤 실패 사례에서 나온 결론인지)는 대체로 생략된다. 그래서 **설계 결정의 근거 자료로 인용하기에는 약하고, 개념 지도와 어휘를 빠르게 갖추는 용도로는 효율적**이다. 이 라이브러리 안에서의 위치도 그렇다 — 여기서 어휘를 얻고, 근거는 논문·1차 문서 쪽 항목에서 가져오는 조합이 맞다.
