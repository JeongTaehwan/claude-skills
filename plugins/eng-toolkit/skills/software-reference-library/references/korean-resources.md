# 국내 자료 (Korean Resources)

영어 원전은 원리를 주지만, 국내 서비스 환경(결제·본인인증·정산·규제·트래픽 패턴)의 구체적 사례는 국내 테크 블로그가 훨씬 낫다. 사용자가 한국어 사례나 국내 맥락을 물을 때 여기부터 볼 것.

## 개발 · 아키텍처 사례

### 우아한형제들 기술블로그
https://techblog.woowahan.com/
국내에서 가장 밀도 높은 기술 블로그 중 하나. 주문·정산·배차 도메인의 실제 설계, DDD·이벤트 기반 아키텍처 적용기, 대규모 트래픽 대응 사례가 많다.
**쓸 때:** 도메인 주도 설계·이벤트 아키텍처의 국내 실사례. 주문/결제 도메인 설계 참고.

**쓸 때:** 금융/결제 도메인, 무중단 배포, 장애 대응 사례.

## 국내 맥락에서 주의할 것

**접근성**: 국내 웹 접근성 인증 심사는 WCAG를 기반으로 하되 국내 지침(KWCAG)을 따른다. 영어 자료를 그대로 적용하기 전에 국내 기준을 확인할 것.

**개인정보·본인인증**: 개인정보보호법과 정보통신망법 요구사항이 설계에 직접 영향을 준다. 해외 사례의 데이터 수집·보관 방식을 그대로 옮기면 안 된다.

**결제**: PG·간편결제·에스크로 요구사항이 주문 도메인 설계를 크게 제약한다. 위 블로그들의 결제 관련 글이 해외 자료보다 훨씬 실용적이다.

이런 규제·컴플라이언스 질문은 이 라이브러리의 범위를 벗어난다. 사례로는 참고하되, 실제 준수 여부는 최신 법령과 법무 검토가 필요하다는 점을 사용자에게 분명히 말할 것.
