# 스킬 작성 규약

`lint_skills.py`가 기계로 확인하는 것은 ✔, 사람이 보는 것은 ○.

## 무게 — 항상 실리는 것과 필요할 때 읽히는 것

| 층 | 언제 컨텍스트에 오르나 | 상한 |
|---|---|---|
| `description` (frontmatter) | **설치된 모든 세션의 매 턴** | ✔ 스킬당 350자, 전체 합 4,200자 |
| `memory/CLAUDE.md` | 매 세션 매 턴 | ✔ 1,500자 |
| 에이전트 `description` | 매 턴 (Agent 도구 설명에 실린다) | ✔ 에이전트당 160자 |
| `SKILL.md` 본문 | 발동할 때 | ✔ 9,000자 (implementation-design 은 예외 12,000자) |
| `references/*.md` | 본문이 지목한 단계에서만 | 상한 없음. 대신 **파일 하나에 주제 하나** |
| `scripts/*` | 실행 결과만 오른다 | 출력이 2천 토큰을 넘으면 요약 모드를 둔다 |

본문에 다 쓰면 발동할 때마다 전부 읽힌다. 단계별로 쪼개 references 에 두면 그 단계에 간 때만 읽힌다.

## 필수 절

- ✔ `## 페르소나` — 3줄 이내. **너는 누구인가 / 상대는 누구인가 / 무엇을 중시하는가.** 같은 절차도 "누구로서" 하느냐에 따라 멈추는 지점이 달라진다
- ✔ 코드 블록 1개 이상 (본문 또는 references) — 절차를 말로만 쓰면 모델마다 다르게 옮긴다. 코드 블록 뒤에는 그 코드에서 가장 중요한 한 줄이 무엇인지 적는다 ○
- ○ 게이트 — 언제 연다 / **언제 안 연다**. 뒤엣것이 오발동을 막는다
- ✔ 본문이 지목한 `references/…`·`templates/…`·`scripts/…` 파일이 실제로 있다

## 최소 단위로 나눠 저장한다

- references 파일 하나 = 주제 하나. 레퍼런스 라이브러리의 "항목 하나 = 파일 하나"와 같은 원리다
- 다른 스킬의 내용을 복사하지 않고 경로로 지목한다 (예: 질문 모드는 `project-flow/references/question-mode.md` 한 곳에만)
- 대체된 규칙은 지우지 않고 `> 대체됨: <새 위치>` 한 줄을 남긴다 — 왜 바뀌었는지가 사라지지 않게

## 훅으로 보낼 것 — 판단이 필요 없는 규칙

| 규칙의 모양 | 둘 곳 |
|---|---|
| "절대 X 하지 마" + X를 명령·경로·문자열로 판정 가능 | **PreToolUse 훅** (exit 2 로 막는다) |
| "끝나면 반드시 Y를 돌려라" | **Stop 훅** (`verify-on-stop.sh`) |
| "몇 번 썼나 세라" | **PostToolUse 훅** (`count-usage.sh`) |
| 상황을 보고 판단해야 한다 | 스킬 본문 |

훅은 토큰을 쓰지 않고 예외 없이 동작한다. 같은 규칙을 본문에도 남길 때는 한 줄로 줄이고 "(훅이 막는다)"를 붙인다 — 훅을 등록하지 않은 컴퓨터에서도 규칙은 살아 있어야 하므로.

## 모델은 별칭으로

에이전트 `model:`은 `opus`/`sonnet`/`haiku`/`inherit`만 쓴다 ✔. 버전 ID를 박으면 새 모델이 나올 때마다 파일을 고쳐야 한다. 모델별 구성은 `profiles/`가 맡는다.
