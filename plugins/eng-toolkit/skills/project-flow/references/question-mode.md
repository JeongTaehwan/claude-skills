# 질문 모드 — 기획서가 있을 때만

## 들어가는 조건

`docs/requirements.md`(기획서)가 있고 `[미정]`이 하나 이상일 때만 질문한다.

| 상태 | 하는 일 |
|---|---|
| 기획서 없음 | **묻지 않는다.** 사람의 말을 그대로 받아 `structure.md` → 기획서 초안을 먼저 만든다. 모르는 칸은 `[미정]` |
| 기획서 있음, `[미정]` 0건 | 묻지 않는다. 승인 요청만 한다 |
| 기획서 있음, `[미정]` n건 | 아래대로 최대 15개 |
| 사람이 외부 기획서를 줌 | 형식만 `requirements.md`로 옮기고(문장은 원문 그대로), 빈 곳을 `[미정]`으로 표시한 뒤 묻는다 |

기획서 없이 15개를 물으면 사람은 머릿속 기획서를 말로 구술하게 되고, 답이 문서 어디에도 자리를 못 잡는다. 초안이 있으면 질문이 칸을 메우는 일이 된다.

## 진행

1. **BLOCKER부터** 5개씩. 라운드당 5개, 최대 3라운드(15개). `[미정]`이 15개보다 적으면 그만큼만.
2. 질문 전에 코드·문서를 조사하는 건 좋다. 조사 결과는 질문의 재료지 답이 아니다.
3. 사람이 "그만" 하면 즉시 마무리. 3라운드가 끝나도 "정리해줘"를 기다리지 않고 마무리.
4. `docs/domain.md`에 이미 답이 있는 것은 묻지 않는다.

## 하지 않는 것

- 기능·스택·아키텍처 제안 — 묻는 자리다
- **질문에 예시 답 붙이기** — 사람이 그 답에 끌려간다
- 사람이 말하지 않은 것을 추측해서 채우기

## 질문 축 (순서대로)

1. 이 화면이 답하는 질문 하나
2. 데이터 주인 — 같은 값이 두 군데 있으면 누가 이기는가
3. 기준과 분모 — 한 화면의 숫자들이 같은 기간·범위·모수를 보는가
4. 범위 밖
5. 모르는 값 — 데이터가 없을 때 화면이 뭐라고 쓰는가 ("없음" ≠ "0" ≠ "판정 불가")
6. 상태 — 빈 값 / 로딩 / 실패 / 표본 부족 / 미확정
7. 제약 — 외부 의존(요금제·쿼터·한도), 기존 계약

## 출력

| # | 질문 | 이거 안 정하면 막히는 것 | 등급 | 기획서 위치 |

- "막히는 것"은 구체적 증상. "혼란이 생긴다" 금지.
- 등급은 BLOCKER(답이 갈리면 구조가 달라진다) / LATER(코드 몇 줄로 바뀐다).
- "모르겠다"면 대신 정하지 않고 `[미정]` + 등급. 여러 기능에 걸치는 답은 `structure.md`의 공유 계약 미정으로 올린다.

## 마무리 — 자동 저장

1. 답을 `requirements.md`의 해당 칸에 반영한다. 상태는 `미승인 초안` 유지. 사람의 말과 정리한 문장이 다르면 사람의 말이 이긴다.
2. 남은 `[미정]`은 등급과 증상을 붙여 `open-questions.md`에도 올린다.
3. `docs/test-cases.md`는 만들지 않는다 (검증 AI 몫, 훅이 막는다).
4. 사람에게 바꾼 파일과 `BLOCKER n건 / LATER n건`을 알리고 승인을 기다린다.

```text
BLOCKER  n건  ← 0이 되기 전에는 정식 구현을 시작할 수 없다
LATER    n건
```
