# 3단계 — 로드맵과 투두

기획서가 정해지면 "무엇을 어떤 순서로"를 자동으로 짠다. 사람이 손으로 쪼개면 공유 계약이 뒤로 밀려 나중에 갈아엎는다.

## 짜는 규칙

1. **마일스톤은 사람이 눌러 볼 수 있는 단위**다. "API 완성"이 아니라 "인원·시간을 넣으면 빈 회의실 하나가 잡힌다".
2. 순서: **공유 계약(데이터 모델·인증·공통 기준) → 핵심 흐름 하나 → 나머지 기능 → 운영(보안·인프라·마케팅)**. 운영 마일스톤은 `security-baseline`·`infra-baseline`·`marketing-growth` 스킬의 체크를 태스크로 옮긴다.
3. **투두 한 줄 = 반나절 이하의 일 하나.** 형식: `- [ ] <동사로 시작하는 일> — R-XX-NN · <에이전트> · 완료 조건`
4. 모든 투두는 기획서 ID를 가리킨다. 가리킬 ID가 없는 일은 투두가 아니라 기획서 미정이다.
5. BLOCKER가 걸린 투두는 `⛔ XX-OQ-NN` 을 붙이고 순서에서 뺀다.
6. 맡는 에이전트를 적는다 — 그래야 실행할 때 모델이 정해진다.

## 갱신

- 체크박스와 맨 아래 집계(완료/전체, 마일스톤별)는 `scribe` (haiku)가 맞춘다. 메인 세션이 세지 않는다.
- 기획서가 바뀌면 영향받는 투두에 `↻ 재검토`를 붙인다. 지우지 않는다.

## 예시

```markdown
## M1 — 인원·시간을 넣으면 빈 회의실 하나가 잡힌다
- [ ] 회의실·예약 스키마 정의 — R-RM-01 · architect · 마이그레이션 up/down 통과
- [ ] 겹침 없는 예약 생성 (조건부 INSERT) — R-BK-03 · developer · 동시 요청 2건 중 1건만 성공하는 테스트 통과
- [ ] 검색 화면 상태 문구 5종 — R-SR-02 · ux-designer · flows.md 에 문구 존재
- [ ] ⛔ BK-OQ-02 반복 예약 허용 범위 — R-BK-07 · (사람 결정 대기)
```

`완료 조건`이 판정 가능한 문장이어야 체크박스가 의미를 갖는다 — "구현함"은 완료 조건이 아니다.
