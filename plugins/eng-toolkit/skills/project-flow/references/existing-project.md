# 0단계 — 기존 프로젝트 전체 분석

코드가 이미 있으면 구조를 상상으로 짜지 않는다. 있는 것부터 지도로 만든다.

## 순서

1. **지도는 스크립트가 그린다.** `repo-map.py`가 언어·매니페스트·진입점·라우트·스키마·테스트·CI·검사 명령 후보를 한 화면에 낸다. 파일을 하나씩 열어 훑으면 수만 토큰이 들고 그게 세션 끝까지 다시 읽힌다.

   ```bash
   python3 ~/.claude/skills/project-flow/scripts/repo-map.py .
   ```

2. **갈림길만 연다.** 지도에서 진입점, 데이터 모델(마이그레이션·ORM 스키마), 라우트/핸들러, 설정 로더만 읽는다. 파일당 필요한 줄만.
3. **검사 명령을 실제로 돌린다.** 타입·린트·테스트·빌드 중 있는 것. 결과(통과/실패 수)를 그대로 적는다. 돌릴 수 없으면 이유.
4. **`docs/analysis.md`** 를 [../templates/analysis.md](../templates/analysis.md) 형식으로 쓴다. 모든 사실에 `파일:라인`.
5. 분석이 끝나면 1단계 구조로 간다. 구조의 "기능 분해"는 **이미 있는 기능**과 **새로 만들 기능**을 나눠 적는다.

## 맡기기

`analyst` (sonnet) 하나로 충분하다. 저장소가 크면(파일 2천 개 이상) 최상위 디렉터리 단위로 `analyst`를 나눠 병렬로 돌리고, 결과를 `scribe`가 한 파일로 합친다.

## 하지 않는 것

- 분석 중에 고치지 않는다. 보이는 문제는 `analysis.md`의 "위험" 절에 적는다.
- 지도를 건너뛰고 전체 파일을 읽지 않는다.
- `.env*` 값은 옮기지 않는다. 변수 이름과 정의 위치만.
