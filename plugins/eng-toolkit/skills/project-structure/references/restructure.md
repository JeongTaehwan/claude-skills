# 재구조화 — 이미 있는 구조를 고칠 때

고치기 전에 `structure_scan.py` 로 잰다 (SKILL.md 2절). 이득을 한 문장으로 — 어떤 변경이 몇 디렉터리에서 몇 디렉터리로 줄어드는가 — 못 대면 하지 않는다.

1. **순서**: 순환 끊기 → 공개 표면 만들기(밖에서 오는 내부 import 를 진입점으로) → 규칙 켜기(기준선으로 얼림) → 이동. 이동부터 하면 규칙 없이 옮긴 자리에서 다시 엉킨다
2. **한 PR 은 이동만, 또는 동작 변경만.** 이동 PR 은 `git mv` 와 import 경로 수정 외에 아무것도 없어야 리뷰가 가능하고, 문제가 생기면 통째로 되돌릴 수 있다
3. **빅뱅 금지.** 기능 하나씩 새 구조로 옮긴다. 두 구조가 몇 주 공존한다는 걸 전제로 "새 코드는 `features/` 에, 옛 `services/` 는 옮기는 중"을 README 한 줄에 적는다
4. **이동 PR 은 짧게 열고 빨리 머지한다.** 열려 있는 동안 다른 브랜치가 전부 충돌한다. 큰 이동은 팀에 미리 알린다
5. **끝나면 다시 잰다.** 순환·커밋당 모듈 수가 실제로 줄었는지 스캔으로 확인한다. 안 줄었으면 폴더만 옮긴 것이다

## PR 단위 계획의 모양

```text
PR 1  순환 끊기        orders → payments 간선을 이벤트로 (OrderPaid). 동작 변경 있음, 테스트 동반
PR 2  공개 표면        features/cart/index.ts 추가, 밖의 내부 import 14건을 진입점으로. 동작 변경 없음
PR 3  규칙 켜기        .dependency-cruiser.js + --baseline. 기존 위반 6건 얼림
PR 4~ 이동            기능 하나씩: git mv src/services/coupon* src/features/coupon/ + import 경로만
마지막 다시 재기        커밋당 모듈 수 중앙값 4 → 1 인지 확인
```

각 줄의 마지막 말("동작 변경 없음")이 리뷰어가 읽는 계약이다. 이동 PR 에 동작 변경이 한 줄이라도 섞이면 그 PR 은 되돌릴 수 없게 된다.
