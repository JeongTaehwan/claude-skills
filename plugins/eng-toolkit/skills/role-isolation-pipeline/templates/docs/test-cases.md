# 기획 인수 테스트

> 검증 AI가 코드 없이 요구사항만 보고 작성한다. 구현자는 수정하지 않는다 —
> 구현자가 통과 기준을 만들면 검증이 성립하지 않는다.
> 자동화 테스트 코드가 아니라, 사람이 [7] 단계에서 직접 눌러보는 인수 테스트 문서다.

## [화면·기능 이름]

| # | 대상 요구사항 | 사전 조건 | 사용자 행동 | 기대 결과 | 확인할 거짓말 방지 조건 |
|---:|---|---|---|---|---|
| XX-01 | | | | | |

작성 규칙:

- `XX`는 화면·기능 약칭이다 (예: 주문 목록 → OL). `docs/open-questions.md`의
  `XX-OQ-` 접두사와 같은 약칭을 쓴다.
- 정상 경로만 쓰지 않는다. 빈 값 / 로딩 / 실패 / 표본 부족 / 미확정 / 시간축 불일치 중
  해당하는 상태를 포함한다.
- "확인할 거짓말 방지 조건" 열에는 화면이 멀쩡해 보이면서 틀리는 경우를 적는다 —
  null을 0으로 표시, 분모 감춤, 부분 데이터를 전체처럼 표시.
- `[미정]` 때문에 기대 결과를 확정할 수 없으면 임의로 완성하지 말고
  `BLOCKED — [미정 항목]`으로 기록한다.
- 기존 파일이 있으면 이번 범위만 갱신하고 다른 범위의 테스트는 보존한다.
- 맨 아래에 총 건수와 BLOCKED 건수를 집계한다.
