# 미정 사항

> 해결된 항목을 삭제하지 않는다 — 상태를 `해결·승인: <한 줄 결정>`으로 바꾼다.
> 삭제하면 "왜 그렇게 정했나"가 사라진다.

## [화면·기능 이름]

| # | 질문 | 이거 안 정하면 막히는 것 | 등급 | 상태 |
|---:|---|---|---|---|
| XX-OQ-01 | | | | `[미정]` |

작성 규칙:

- 접두사는 화면·기능 약칭 + `-OQ-` + 번호 (예: 주문 목록 → `OL-OQ-01`).
- 등급은 BLOCKER / LATER 둘 중 하나.
  - **BLOCKER** — 답이 갈리면 구조가 달라진다. 0이 되기 전에는 구현을 시작할 수 없다.
  - **LATER** — 구현하며 정해도 된다. 코드 몇 줄로 바뀐다.
- "막히는 것"은 구체적 증상으로 쓴다. "혼란이 생긴다" 금지.
- 답이 나오면 상태를 `해결·승인: <결정>`으로 바꾸고 아래 집계에서 뺀다.

```text
BLOCKER  0건
LATER    0건
```

---

## 프로세스 미정 (PROC-OQ)

화면·기능이 아니라 파이프라인 절차 자체의 문제는 여기에 `PROC-OQ-NN`으로 기록한다.

- 날짜와 어느 사이클에서 발견했는지
- 증상 — 무엇이 불편했나
- 방향 — 어떻게 고칠 수 있을지 (정해진 것은 아님)
