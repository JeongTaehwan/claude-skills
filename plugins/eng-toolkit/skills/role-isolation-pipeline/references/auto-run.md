# 자동 진행 구간 — [5]부터 [8] 호출까지


"구현해줘" 한 번으로 설계 판단 → 코드 변경·추가 → 자동화 테스트 작성·실행 →
타입·린트·빌드 검사까지 사람에게 묻지 않고 진행한다. [6]이 실패하면 요구사항 범위 안에서
고쳐 다시 돌리고, 통과하면 검증 AI 리뷰를 자동 호출한다 (아래 규칙). 단, 진행 중 문서에
없는 판단이 필요해지면 자동 진행이 아니라 멈춤이다 — `open-questions.md`로 올리고 보고한다.

**리뷰 자동 호출 규칙 — 배관은 자동, 판단은 사람.**

- 호출은 검증 AI CLI의 비대화형 실행으로 하고, **전달하는 것은 diff뿐이다.**
  구현 의도·설명을 함께 넘기지 않는다 (불변 규칙 2의 기계적 보장).
- 리뷰 결과가 오면 [6] 결과 원문 + 리뷰 지적 표 + 요구사항별 확인 목록을 **한 번에**
  사람에게 보고하고 멈춘다. 사람은 [7] 직접 눌러보기와 [9] 판단을 이 시점에 같이 한다.
- **지적을 고칠지는 항상 사람이 정한다.** 구현자가 자기 코드에 대한 지적의 수용 여부를
  스스로 판단하면 그게 곧 스스로 리뷰하기다. 사람이 "고칠 것"으로 표시한 항목만 수정한다.
- 수정 후에는 [6] 재실행 → 재리뷰 자동 호출. 새 지적이 나오면 다시 사람 판단으로.
  이 수정→재리뷰 반복이 **2회를 넘으면** 자동 호출을 멈추고 상황을 보고한다 —
  두 AI가 진동하고 있다는 신호다.
- 검증 AI를 비대화형 CLI로 호출할 수 없는 프로젝트면 이 절은 수동으로 돌아간다:
  완료 보고 후 사람이 리뷰를 시킨다.


## 코드 예시 — 리뷰 자동 호출 (diff만 넘긴다)

```bash
# 프로젝트 CLAUDE.md 의 "리뷰 자동 호출 [8]" 자리에 들어가는 형태.
# 검증 AI CLI 이름과 플래그는 벤더마다 다르다 — 아래는 모양만 보여준다.
git diff --no-color origin/main...HEAD -- . ':(exclude)docs/test-cases.md' > /tmp/review.diff
<verifier-cli> --non-interactive \
  --instructions-file AGENTS.md \
  --input /tmp/review.diff > docs/review/$(date +%F)-code.md
```

넘기는 파일이 `AGENTS.md`와 diff 둘뿐이라는 것이 불변 규칙 2의 기계적 보장이다 — 구현 의도를 설명하는 한 줄을 프롬프트에 덧붙이는 순간 검증자가 동조자가 된다.
